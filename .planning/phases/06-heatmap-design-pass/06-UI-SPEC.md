# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope note — read before using this document

Per `06-CONTEXT.md` D-26, this phase's chosen heatmap treatment (winning plot form, exact
palette stops, hatch geometry, fixed-domain endpoints) is decided **during phase execution**, by
building and judging four throwaway mockups against real swept data — not by pre-work research.
That decision is recorded in `06-HEATMAP-SPEC.md` plus a PROJECT.md Key Decision, not here.
D-26 explicitly rejects a `06-UI-SPEC.md` used alone as the record of that choice, on the grounds
that this template has no home for "form A won, forms B/C/D lost, here is why."

This document instead locks what CONTEXT.md's decisions already fix independent of which form
wins: the reused design-system tokens (spacing, typography, theme mechanics, the destructive
color), the copywriting this phase owns (the VIZ-10 caveat, the legend labels), and the
already-locked constraints on the colour treatment (diverging, symlog, one background-neutral
palette, fixed domain, categorical hatch/grey rules) that whichever form wins must satisfy.
Where CONTEXT.md leaves a value to Claude's Discretion (exact palette stops, domain endpoints,
hatch geometry, caveat wording within its two-sentence structure), this document states the
constraint and defers the specific value to `06-HEATMAP-SPEC.md`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Solid.js for the D-05 comparison page; plain HTML/vanilla JS for the four mockup files (D-28), outside `src/` and the Vite build |
| Icon library | none — no icons are needed for this phase; the only interactive element is the theme toggle, reused verbatim from `src/app/theme.ts` |
| Font | system stacks only, unchanged from Phase 4. UI text: `system-ui, -apple-system, "Segoe UI", sans-serif`. Numerics (legend ticks, axis labels): `ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace` |

**Why no shadcn:** already settled in `04-UI-SPEC.md` — shadcn has no official Solid.js support, and this project's stack is Solid.js, not React. Not re-litigated here.

**Why the mockups still follow this contract despite living outside `src/`:** D-28 keeps all four mockups committed and judgeable long after decision day, importing the D-27 colour function and D-29 fixture from `src/` rather than inlining copies. Following the same spacing/typography/theme tokens the app already uses means a mockup's surrounding chrome (panel padding, legend, caveat copy) does not need a second design pass if any of it is reused later, and keeps the four-way comparison an apples-to-apples judgement of plot form rather than of incidental styling differences.

## Spacing Scale

Declared values (must be multiples of 4), reused unchanged from `04-UI-SPEC.md`:

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | Gap between a legend tick mark and its numeric label |
| sm | 8px | Gap between the legend ramp and the two detached categorical swatches (D-25) — the gap itself is the "detached" signal |
| md | 16px | Gap between the grid/plot area and the VIZ-10 caveat copy line (D-21: directly under the grid, above the legend); gap between the caveat line and the legend below it |
| lg | 24px | Outer padding of each mockup panel on the D-05 comparison page |
| xl | 32px | Gap between adjacent mockup panels on the comparison page |
| 2xl | 48px | Gap between the four-panel comparison section and any page-level heading, if one is added |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Per-form display geometry (D-12) — cell size, strip width, contour band width — is a rendering decision each form makes independently, not a spacing-scale value. Out of this contract's scope; see `06-HEATMAP-SPEC.md` once forms are built.
- Hatch stroke width and spacing (D-18, F-03) is likewise per-form and not on this scale — it must be legible at that form's own cell size, which the 8-point scale does not constrain.

**The heatmap's own value-to-color mapping is deliberately not specified here.** Deciding it is this phase's work, not this document's. What CONTEXT.md already locks, and whichever form wins must satisfy — recorded in full, with exact values, in `06-HEATMAP-SPEC.md`:

| Constraint | Source | Detail |
|------------|--------|--------|
| Scale type | D-13 | Diverging, centred exactly at 1.0x (the breakeven). Never sequential for this metric. |
| Family | D-13 | Blue-orange or purple-green — never red-green (PITFALLS E3), which also keeps the ruin red unambiguous |
| Non-linear map | D-14 | Symmetric log (symlog) about 1.0x: `log10(multiple)`, diverging centre at `log10(1.0) = 0` |
| Theme handling | D-15 | One background-neutral palette, mid-luminance midpoint, shared by both themes — no theme-swapped variant |
| Domain | D-16 | Fixed, stated on the legend, clipped beyond its endpoints — never fitted per-sweep. Exact endpoints: Claude's Discretion, resolved in `06-HEATMAP-SPEC.md` |
| Ruin | D-18 | Hatched fill in the destructive color above, own legend entry — never flat black or flat destructive red |
| Incomplete-hold | D-20 | Flat muted grey, carries no value, own legend entry — never a faded real color |
| CVD check | D-17 | An automated test (adjacent bands stay perceptually separable under protanopia/deuteranopia/tritanopia simulation), not a committed image. Perceptual-distance metric and threshold: Claude's Discretion |

## Copywriting Contract

|---------|------|

| Empty state | Not applicable — every mockup renders a real precomputed sweep (D-03); there is no empty-data state to design |

| **Legend — incomplete swatch (D-25)** | "Holding period incomplete" |
| **Panel titles (D-05)** | "Dense grid", "Filled contour", "Small multiples", "Grid + contour overlay" — plain, descriptive, not marketing copy; this is a working comparison tool for judging, not shipped UI |

## UI Considerations

Static-content-heavy phase: no forms, no data-fetch-driven loading beyond the one-time fixture
read, and only one reused interactive control (the theme toggle). Applied the shape-rooted
taxonomy by hand rather than via the automated probe, given the small element count.

Applicable state considerations resolved: **10 resolved (7 explicit, 3 backstop), 8 dismissed with reason, 0 unresolved.**

### E1 — Comparison page (D-05)

_Kinds: list-collection, static-content_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | dismissed | Exactly four mockups always render (D-02 fixes the count); there is no zero-mockup state to design |
| loading | explicit | The page fetches the D-29 fixture once before any panel paints; all four panels stay hidden until it resolves — no per-panel spinner, consistent with Phase 4's "no blank pane with a spinner" rule (PITFALLS F4) |
| error | 🧪 backstop | CONTEXT.md specifies no treatment for a fixture load failure. Since this is a dev-only comparison tool, resolve by failing loudly (visible broken state, not silently blank) — verify visually rather than asserting a specific message |
| populated | explicit | Typical (only) volume is exactly four mockup panels, each at its own D-12 geometry, reflowing per theme (D-06) and viewport |
| partial | dismissed | No partial state — all four mockups read the same committed fixture; either all render or the page fails to load |
| overflow | 🧪 backstop | Four panels at differing native geometries (D-12) share one page; verify none pushes another off-screen or forces horizontal scroll at typical comparison-viewing widths |
| zero-one-many | dismissed | Fixed at exactly four (D-02) — not a variable-length collection |
| long-text | explicit | The page's only variable-length text is the caveat copy (E3) and legend (E4) below, both covered separately |

### E2 — Mockup panel (four forms)

_Kinds: media, static-content_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | dismissed | D-03 requires all four forms to render from a real precomputed sweep; there is no empty-data variant to design |
| loading | dismissed | Covered once at E1 (page-level fixture load); individual panels have no independent loading state |
| error | dismissed | Same as above — a fixture load failure is page-level, not per-panel |
| populated | explicit | Each panel renders the full 10,000-cell field at its own D-12 geometry, on the D-04 primary metric (multiple-of-contributed) and, for winning candidates, the max-drawdown stress case, in both themes (D-06) |

### E3 — VIZ-10 caveat copy

_Kinds: static-content_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| overflow | explicit | Every mockup renders the real two-sentence copy at real panel width (D-23). A form that cannot fit it without shrinking or pushing it off-screen loses on criterion 3's own terms — this is a judging input by design, not a bug to fix |
| long-text | explicit | Copy wraps to whatever height it needs (Body role, 1.5 line-height) rather than truncating; D-21 reserves a fixed slot directly under the grid, above the legend, so each panel must budget room rather than clip |

### E4 — Legend

_Kinds: static-content_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| overflow | 🧪 backstop | Five ramp ticks plus two detached categorical swatches (D-25) must fit under each form's own geometry (D-12); verify at each mockup's actual panel width that ticks do not collide with or overlap the swatches |
| long-text | explicit | Tick labels are bounded fixed-format numerics via `src/metrics/format.ts`; swatch labels are two short fixed strings with no variable-length content |

### E5 — Theme toggle (reused)

_Kinds: interactive-control_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| loading | dismissed | Reuses `src/app/theme.ts` verbatim, already resolved in `04-UI-SPEC.md` — not re-litigated here |
| error | dismissed | Same as above |

Rows marked 🧪 backstop are not under-specified by omission — each is a question only a rendered pixel can answer (panel collision, legend fit at a form's real geometry) and must be discharged by visual inspection during the D-05 comparison step, which CONTEXT.md's `<specifics>` already treats as real work with a real artifact, not a formality.
