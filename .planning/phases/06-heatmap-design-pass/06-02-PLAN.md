## Thresholds, fixed before the palette is tested

These four numbers are set here so no later step can tune them to a result. Prohibition: if the
palette fails against them, the PALETTE changes, never these.

| Constant | Value | Source |
|---|---|---|
| `CVD_BAND_COUNT` | 16 | Sixteen bands means fifteen adjacent pairs across the full ramp, a granularity a reader actually resolves on a 4px cell field |
| `MIN_ADJACENT_DELTA_E` | 3.0 | Mahy et al. 1994's widely cited CIE76 just-noticeable difference of 2.3, plus margin, because dichromacy simulation compresses the gamut and can only bring a pair closer together, never further apart (`06-RESEARCH.md` assumption A2) |
| `MIN_CATEGORICAL_DELTA_E` | 10.0 | The incomplete-hold grey is not merely distinguishable from its neighbours, it must read as a different KIND of thing than any valued cell (D-20, PITFALLS E5) |
| Simulation method | Vienot, Brettel and Mollon 1999 | The simplest of the three legitimate published methods to implement correctly in the roughly fifty lines D-17 budgets: sRGB decode, one 3x3 matrix multiply, sRGB encode, with no per-pixel half-plane geometry |

  <action>
Write `tests/color-scale-cvd.test.ts` in the fast Node `unit` project. It is pure colour-space
maths over `valueToColor`'s own output, so it needs no DOM, no canvas and no browser.

Implement, test-locally, in roughly fifty lines total (D-17's own budget, no dependency):

- `srgbToLab(rgb)`: sRGB companding, the D65 sRGB to XYZ matrix, then XYZ to CIE Lab with the
  standard `f(t)` piecewise function.
- `deltaE76(labA, labB)`: Euclidean distance in Lab.
- `CVD_MATRICES`: the three Vienot, Brettel and Mollon 1999 dichromacy projection matrices,
  transcribed from `github.com/DaltonLens/libDaltonLens` (public domain, unit-tested). Record the
  source URL and the specific file and function the coefficients come from in a comment above the
  constant. Do NOT transcribe from the widely circulated Coblis or colorjack matrices: their own
  author describes that set as an inaccurate one-night hack, and a plausible-looking wrong matrix
  passes code review while silently defeating the exact thing this test exists to catch
  (`06-RESEARCH.md` Don't Hand-Roll).
- `simulateCvd(rgb, deficiency)`: linearise sRGB, apply the matrix, re-encode to sRGB, clamping
  each channel into 0 to 255 and rounding.

Then assert the behaviours listed above. Sample the ramp by evaluating
`valueToColor({ value, ruined: false, incomplete: false })` at the `CVD_BAND_COUNT` values whose
ramp positions are the band centres, computed by inverting the symlog transform over
`[DOMAIN_LOG_MIN, DOMAIN_LOG_MAX]`, so the sampled bands are the bands a reader actually sees
rather than an arbitrary set of numbers.

Do not assert colour separability for `RUIN_BASE_RGBA`. Ruin is deliberately the same destructive
hue the ruin banner and the equity-curve terminator already use, and under deuteranopia it will
sit close to the warm end of the ramp; D-18 resolves that with TEXTURE, which is not a colour
channel and therefore cannot be measured by this test. State that in a comment so a later reader
does not mistake the omission for an oversight, and note that the hatch is what carries ruin's
categorical distinctness.

Write no image file. Criterion 2 is satisfied by this live check plus the written finding, never
by a binary artifact (D-17).
