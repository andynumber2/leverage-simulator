## Resolved before execution: do not re-litigate

1. **Serving.** The mockups are served by the repo's existing `vite dev` (`npm run dev`), not
   `file://`. This was verified empirically at plan time on this repo at Vite 8.2.1: a request to
   `/.planning/phases/06-heatmap-design-pass/mockups/<name>.html` returns 200 with the
   `/@vite/client` shim injected, `/src/metrics/format.ts` returns 200 with TypeScript types
   stripped, `/src/app/theme.ts` returns 200, and a `.bin` under the same directory returns 200.
   D-28's "no build step" means the mockups are absent from `vite build`'s output, which stays
   true because nothing under `.planning/` is reachable from the root `index.html` entry.
2. **No new dependency.** `06-UI-SPEC.md` Registry Safety binds the whole phase. Its D-14
   attribution is a citation error, but the constraint is stated independently in `06-CONTEXT.md`
   line 435. `d3-contour`, `marchingsquares`, `d3-scale`, `d3-interpolate` and
   `d3-color-difference` are all out. Every routine in this phase is hand-rolled. No task in any
   Phase 6 plan runs a package-manager install.
3. **Legend tick format.** `formatMultiple` from `src/metrics/format.ts` is called directly, so
   the D-24 ticks read `0.10x`, `0.50x`, `1.00x`, `2.00x`, `10.00x`. `06-UI-SPEC.md`'s bare-integer
   copy examples (`1x`, `0.1x`) are illustrative of which values get ticks, and its own
   Typography section instructs reuse of the existing formatter with no second formatter. No
   trimming step is added.
4. **Where the colour function lives (finding F-05).** `src/colorscale/`, a new sibling of
   `src/metrics/`. It cannot live under `src/app/` because the mockups are plain HTML, it is not
   kernel code and it is not data-layer code, and siting it outside `src/kernel/` keeps
   `tests/kernel/module-boundary.test.ts`'s `ALLOWED_SPECIFIERS` set untouched. The kernel never
   imports it in either direction.
5. **Where the sweep script lives, and how big it is (finding F-06).** `scripts/`, beside
   `run-backtest.ts` and `measure-extended-tier-bias.ts`, which are its two closest precedents.
   F-06 is right that this is a small compiler rather than a fixture generator: it runs the kernel
   10,000 times against real bundle data, resolves a 20-year holding window per cell, detects two
   categorical states, computes two metrics and serializes a versioned binary. It carries the same
   day-count and fraction-versus-percentage discipline the kernel tests enforce, and this plan's
   task sizing reflects that rather than treating it as a detail.

## Planner findings surfaced at plan time

Two consequences of the locked axis decisions that the executor should meet as known facts rather
than discover mid-task. Neither changes a decision; both are measured rather than assumed by the
script this plan writes.

- **The incomplete-hold region is roughly half the entry axis, not a thin edge.** D-09 spans the
  full SPX total-return strict tier, which the compiled manifest records as 1988-01-05 to
  2026-08-14, a span of about 38.6 years. D-10 and D-11 fix a 20-year hold, so the newest entry
  date with a complete window is about 2006-08-14 and roughly 52 percent of the 200 columns fall
  in D-19's incomplete-hold state. `06-RESEARCH.md` estimated "roughly the final 20 percent of the
  columns"; that estimate is low. D-19 chose deliberately to show the truncated region rather than
  crop to where the data looks complete, so this is the decision working as intended at a larger
  scale than the research note implied. The script prints `incompleteCount` so the real figure is
  a fact, and plan 06-06 records it in the spec.
- **The fixture may contain zero ruined cells.** D-08 caps leverage at 5x and D-09 starts the
  entry axis in 1988. The kernel ruins a position when its value reaches zero, which at 5x needs a
  single daily return at or beyond roughly -20 percent. The worst daily return in the 1988 onward
  window is about -12 percent, so no cell may ruin at all. D-03's "1929-adjacent ruin corner" is
  reachable only through the extended-tier span D-09 explicitly rejected. The script prints
  `ruinedCount` so this is measured rather than assumed. If it is zero, D-18's hatch is still
  implemented, still unit-tested and still rendered in the D-25 legend swatch, but it is judged
  from that swatch rather than from an in-field region, and plan 06-06 records that limitation
  plainly instead of letting the spec imply the hatch was judged in situ.

Build the five layers of the spine in one slice. No stubs: every layer is the production version.

**(a) `src/colorscale/value-to-color.ts` (D-27a).** Zero imports, so both a plain HTML mockup and
Phase 7's Solid renderer can consume it. Export `Rgba` as a readonly 4-tuple, `ColorScaleInput`
with fields `value`, `ruined`, `incomplete`, and `valueToColor(input): Rgba`. Branch order:
`ruined` first returns `RUIN_BASE_RGBA`, then `incomplete` returns `INCOMPLETE_RGBA`, then the
continuous path (D-18, D-20). The continuous path takes `Math.log10` of the value floored at
`Number.MIN_VALUE`, clamps into `[DOMAIN_LOG_MIN, DOMAIN_LOG_MAX]` set to `-2` and `+2` (D-16),
normalises to `t` in `[0, 1]`, and returns `interpolateRamp(t)`. Because the domain is symmetric
about zero, `log10(1.0) = 0` lands at exactly `t = 0.5`, which is the midpoint stop (D-13, D-14).
Do not derive the domain from the fixture: it is a committed constant.

Interpolate in Oklab, not sRGB, because VIZ-07 requires perceptual uniformity. Implement
`srgbToOklab` and `oklabToSrgb` as the standard sRGB transfer function plus the two fixed 3x3
matrices, and `interpolateRamp` as piecewise-linear interpolation in Oklab between the stops,
converting back to sRGB with per-channel clamping to `[0, 255]` and integer rounding. Starting
`RAMP_STOPS`, blue to neutral to orange per D-13's blue-orange family, never red-green (PITFALLS
E3): `t=0.00` `#08519C`, `t=0.25` `#6BAED6`, `t=0.50` `#A9A29A`, `t=0.75` `#FDAE6B`, `t=1.00`
`#A63603`. The midpoint is a low-chroma WARM neutral at roughly L* 66 rather than a pure grey,
deliberately: D-15 wants a background-neutral midpoint that reads on both `#F5F6F7` and
`#14161A`, and D-20's incomplete-hold grey must stay separable from it.

`RUIN_BASE_RGBA` is the light-theme destructive colour `#C4341F` (D-18; the hatch texture, not the
hue, is what makes ruin categorical, so one hue serves both themes). `INCOMPLETE_RGBA` is
`#6E7378`, a cooler and roughly 20 L* darker grey than the ramp midpoint, so a reader can tell an
unfinished hold from a break-even outcome (D-20). Export `LEGEND_TICK_MULTIPLES` as
`[0.1, 0.5, 1, 2, 10]` (D-24) and `rampPositionFor(multiple)` returning the same `t` the
continuous path computes, so the legend can place each tick at its true symlog position without
re-deriving the transform.

Do not carry over `bench/canvas-grid.ts`'s green-channel-fixed-at-64 trick: it is a
paint-equivalence artifact local to that file (D-27 says read the precursor, do not extend it).

**(b) `src/data/sweep-fixture-format.ts` (D-29).** Follow `binary-format.ts`'s magic plus version
plus fail-loud shape, with a new layout and a new magic. Export `SWEEP_MAGIC` as a distinct
uint32 (not `0x4c56_4744`, which the bundle assets already use), `SWEEP_FORMAT_VERSION = 1`,
`CELL_FLAG_RUINED = 1`, `CELL_FLAG_INCOMPLETE = 2`, `SweepFixtureFormatError`,
`encodeSweepFixture(fixture): Uint8Array` and `decodeSweepFixture(buffer): SweepFixture`.

Layout, little-endian throughout: uint32 magic, uint16 formatVersion, uint16 reserved (zero),
uint32 cols, uint32 rows, uint32 metaByteLength, then `metaByteLength` bytes of UTF-8 JSON, then
zero padding to the next multiple of 8. Payload after the padding: `Float32Array` of
`cols * rows` multiple-of-contributed values, `Float32Array` of `cols * rows` max-drawdown
values, `Uint8Array` of `cols * rows` flag bytes, then zero padding to a multiple of 8. The JSON
meta block carries `bundleVersion`, `symbol`, `dividendReinvest`, `entryDates` (array of ISO
strings, length `cols`), `leverages` (array of numbers, length `rows`), `holdingYears`,
`initialInvestment`, `expenseRatioPercent`, `financingSpreadPercent`, `ruinedCount`,
`incompleteCount`, `minMultiple`, `maxMultiple`, `clippedBelowCount`, `clippedAboveCount`.

`decodeSweepFixture` throws `SweepFixtureFormatError` naming both the found and the expected value
when the magic does not match, when the format version does not match, when the JSON meta block
fails to parse, when `entryDates.length` is not `cols` or `leverages.length` is not `rows`, and
when the buffer's total byte length does not equal the exact length the header implies. That last
check is what keeps a truncated or padded fixture from being read as a plausible field and what
stops a corrupted length from driving a runaway typed-array allocation in the browser.

the row range is exactly 1.00x to 5.00x in roughly 0.0816x steps (D-08). Entry column `j` resolves

`manifest.series.find(s => s.id === 'SPX/total-return').tiers.strict`, convert `firstDate` and

`last`, and take `first + Math.round(j * (last - first) / 199)` for `j` in 0 to 199 (D-09's "full

Per cell, build a `BacktestRequest` with `symbol: 'SPX'`, `dividendReinvest: true` (D-11 total

`expenseRatioPercent: GENERIC_3X_EXPENSE_RATIO * 100` and
`financingSpreadPercent: FINANCING_SPREAD_DEFAULT * 100` from
`src/validation/cost-parameters.ts`. Holding mode is a FIXED 20-year period, never hold-to-today

script's own loop). A cell whose `buildKernelInputs` or `runBacktest` call throws aborts the whole
sweep with the offending row, column, leverage and entry date named; never skip a cell and never
emit a hole.

The script prints, and stores in the meta block, the counts the design pass must not estimate:
`ruinedCount`, `incompleteCount`, `minMultiple`, `maxMultiple`, and the number of complete cells

`clippedBelowCount` and `clippedAboveCount` (D-16's knowingly-accepted clipping, made a measured
figure rather than an assumption). Two runs must produce byte-identical output: the script takes
no arguments, reads no clock and no randomness, and JSON meta keys are emitted in a fixed order.

Write the result to `.planning/phases/06-heatmap-design-pass/mockups/sweep-fixture.bin` and commit
it (D-29). Expect roughly 90KB.
