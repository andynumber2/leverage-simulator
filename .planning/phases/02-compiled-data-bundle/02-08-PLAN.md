## User story

**As a** person who clones this repository and wants to check a number, **I want to** find the vendor's own bytes committed beside every derived series and a set of instructions that describes what the code actually does, **so that** I can re-derive any series myself and refresh the data without reading the source to work out where it comes from.

<objective>
Make the written record match the code, without erasing the record of the mistake.

Two instruction documents currently describe a vendor that is no longer used, a route that no longer exists and a total-return shortfall that no longer exists. They are procedures someone follows, so they are rewritten. Two decision rows in the project record describe why that vendor was chosen and what was learned. They are history, so they are marked superseded and left standing.

Then commit the vendor originals. D-26 accepted the repository cost specifically so that the dividend events the reconstruction is built from exist somewhere in the repository, because the vendor can change them and a derived CSV alone would leave nothing to check against.

Purpose: the reversal happened because a vendor claim was written down as fact and never confirmed by a real pull. The correction is worth nothing if the documents that led there are quietly overwritten and the next reader has no way to see that it happened.
Output: two rewritten procedures, two superseded rows with pointers, two replacement rows, and roughly twelve megabytes of committed vendor bytes.
</objective>

The last two are knowingly accepted risks recorded rather than resolved, on exactly the terms the previous vendor's were.

### The two genuinely manual sources

Both need a browser export followed by a spreadsheet-to-CSV conversion, which is why they are manual rather than because of a bot challenge:

- **Nasdaq**, the Nasdaq-100 total-return index history, downloads as a spreadsheet from the index site and is converted once to `raw/manual/XNDX.csv`. The converted file must keep its byte order mark, its carriage returns and its descending row order untouched, because `normalizeNasdaq` handles all three and a well-meaning cleanup would only make the file differ from what the parser was tested against.
- **Shiller**, the monthly dividend input, downloads as `ie_data.xls` and is converted once, keeping the sheet whose header row carries the literal date, price and dividend column names, to `raw/manual/SPX-DIV-MONTHLY.csv`. The date cells must survive as text of the year-point-fraction form rather than being reformatted into a spreadsheet date type.

### The Yahoo fallback recipe

Keep the request template as a documented recipe, since D-27 makes the manual path a supported route rather than an emergency. Record what was established during the manual download session: the chart API answered a real browser directly but returned a rate-limit status to the development sandbox from both API hosts on the first request, regardless of headers, while the vendor's own web host returned success from the same machine. That is an address-level block against a shared egress address, not a malformed request, and no header change fixes it. Record the wide date-range value that succeeded for the S&P index symbol, the safe default for anything whose history starts after 1970, and the hundred-year-range error the wide value produced on another symbol.

Also record what the run does when it falls back: it says so per series, it stamps the sidecar with the newest observation's date rather than the run date, and it fails outright when a manual file's newest observation is older than that source's declared threshold. Give the actual threshold values from `sources.ts`, and say plainly that there is no flag to bypass the check, on D-11's grounds.

### The two replacement decision rows

Append to `.planning/PROJECT.md`'s decision table, in the same three-column form every existing row uses:

1. **Yahoo and Nasdaq licence positions are knowingly accepted risks (D-05, D-06).** Rationale: names the accepted risk per vendor, states that FRED and Shiller remain explicitly redistributable, and records that the terms text is authored once per source in the source table, copied by the compiler into the manifest and rendered by the Phase 5 methodology page, never hand-typed per file. Outcome: accepted.

Outcome: implemented, with the declared threshold values named.
