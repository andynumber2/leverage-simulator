<assumption_delta_decision>
**Noun now primary:** `Series`, keyed by the composite `SeriesKey = { scope, kind }`, where `scope` is a symbol ticker for symbol-bound series and a reserved shared scope (`@rate`, `@calendar`) otherwise, and `kind` is one of `price-return`, `total-return`, `rate`, `calendar`.

**Decision:** `promote`.

**Rationale:** the naive model makes `symbol` primary and hangs a price-return and a total-return series off it, but the shared short-rate series has no symbol at all, so a symbol-primary model needs an exception in its own base case. D-14 independently keys tiers on `(symbol, dividend mode)` and D-18 makes "one asset per symbol" a packaging fact rather than an identity fact, so the composite is already the real primary everywhere except the naming. The manifest is therefore keyed by `series[]` with each entry carrying its own scope, kind, provenance, seams and tier ranges; `assets[]` is a secondary index from file to the series it contains. Demoting the symbol to a container attribute is what keeps the rate series, the calendar and any future third kind from each needing a special case.

**Suggested contract test (optional, not required by this plan):** a test asserting that every `assets[].series` entry resolves to exactly one `series[].id` and that the two collections have no orphan on either side, so the container index can never drift from the identity list.

### Binary layout (`binary-format.ts`), little-endian throughout

| Offset | Type | Field | Notes |
|---|---|---|---|
| 0 | uint32 | `magic` | `MAGIC`, the fixed value `0x4C564744` |
| 4 | uint16 | `formatVersion` | `FORMAT_VERSION`, the value `1` |
| 6 | uint16 | `assetKind` | `1` calendar, `2` series container |
| 8 | uint32 | `bundleVersionByteLength` | UTF-8 byte length of the bundle version string |
| 12 | uint32 | `descriptorCount` | number of series descriptors that follow |
| 16 | uint32 | `headerByteLength` | byte offset at which the data section starts, always a multiple of `DATA_SECTION_ALIGNMENT` |
| 20 | uint32 | `dataByteLength` | byte length of the data section |
| 24 | bytes | `bundleVersion` | UTF-8, `bundleVersionByteLength` bytes, then padded to the next 4-byte boundary |

Each descriptor, in order, 4-byte aligned:

| Type | Field | Notes |
|---|---|---|
| uint16 | `kindCode` | `1` price-return, `2` total-return, `3` rate, `4` calendar |
| uint16 | `idByteLength` | UTF-8 byte length of the series id |
| uint32 | `calendarStartIndex` | index into the shared calendar array (D-21); `0` for the calendar asset itself |
| uint32 | `length` | number of values |
| uint32 | `dataByteOffset` | byte offset of this series' values, relative to the start of the data section |
| bytes | `id` | UTF-8, padded to the next 4-byte boundary |

`DATA_SECTION_ALIGNMENT` is `8`. The header is padded up to that alignment so that `new Float64Array(buffer, headerByteLength + dataByteOffset, length)` is constructible. A `Float64Array` view over a non-multiple-of-8 byte offset throws a `RangeError`, so this padding is load-bearing, not cosmetic.

Calendar asset data section: one `Int32Array` of days-since-epoch values, strictly ascending, no duplicates. Series container data section: one contiguous `Float64Array` run per descriptor, in descriptor order.

### Series identity

`SeriesKind` is the union `'price-return' | 'total-return' | 'rate' | 'calendar'`. A series id is `` `${scope}/${kind}` ``. `SCOPE_PATTERN` is `/^[A-Z0-9._-]+$/`, applied to any scope derived from a raw filename. The reserved shared scopes are `@rate` and `@calendar`; `@` is outside `SCOPE_PATTERN`, so a raw file can never produce a scope that collides with a shared one.

### Sidecar (`raw-input.ts`)

`SidecarMeta` fields, all required, all strings unless noted: `source`, `url`, `retrievedAt` (ISO `YYYY-MM-DD`), `seriesKind` (one of `price`, `total-return`, `rate`, `dividend-monthly`), `license`, `termsUrl`, `scope`, `units` (one of `index-level`, `percent-annualized`, `ratio`). Validation is an explicit field allowlist: unknown keys abort, and no parsed object is ever spread into a compiler-owned object.

### Manifest (`manifest.ts`)

```
Manifest {
  formatVersion: number
  bundleVersion: string
  calendar: { file, bytes, length, firstDate, lastDate }
  assets: Array<{ file, bytes, series: string[] }>
  series: ManifestSeries[]
  calendarExceptions: Array<{ scope, date, reason }>
}

ManifestSeries {
  id, scope, kind, asset, calendarStartIndex, length,
  firstDate, lastDate, units,
  sources: Array<{ source, url, retrievedAt, license, termsUrl }>,
  seams: SeamRecord[],
  tiers: { strict: DateRange | null, extended: DateRange | null }
}

DateRange { firstDate: string, lastDate: string }
```

`computeBundleVersion` returns the first 12 hex characters of the SHA-256 of `FORMAT_VERSION` joined with every emitted asset's own content hash in sorted filename order. It contains no wall-clock value, so recompiling identical inputs produces an identical bundle version.

### Seam record (`seams.ts`), D-16

`SeamKind` is `'splice' | 'interpolation' | 'carry-forward'`. `SeamRecord` carries `kind`, `firstDate`, `lastDate`, `sourceBefore`, `sourceAfter`, `method`. `SeamCollector` accumulates records and returns them sorted by `firstDate` ascending then `kind` ascending. Later plans populate these; this plan defines the type and emits an empty array per series.

### Tier ranges

`ManifestSeries.tiers` is present from this plan with both fields set to the series' own full range, and plan 02-04 replaces that with the computed values. This keeps the manifest schema fixed from the first commit, per D-16's `costly` reversibility rating.

`binary-format.ts` is the one place the layout is defined. Export `MAGIC`, `FORMAT_VERSION`, `DATA_SECTION_ALIGNMENT` (re-exported from `encode.ts` or defined here, pick one place and import it everywhere else), the `AssetKind` and `SeriesKind` unions, the `SeriesDescriptor` and `AssetHeader` interfaces, `encodeHeader`, `decodeHeader`, `seriesView`, `calendarView`, and `BundleVersionMismatchError`. Implement exactly the byte layout in this plan's `<interfaces>` table, little-endian, with the header padded up to `DATA_SECTION_ALIGNMENT` before the data section starts. `decodeHeader` throws a named error when `magic` or `formatVersion` disagrees with the constants. `seriesView` returns `new Float64Array(buffer, header.headerByteLength + descriptor.dataByteOffset, descriptor.length)` and `calendarView` returns the equivalent `Int32Array`. Do not declare a parallel copy of any of these types in `encode.ts`, in a test, or anywhere else.

`raw-input.ts` implements Pattern 1 unconditionally and first. `loadSidecarOrThrow(csvPath)` derives the sidecar path by replacing the trailing `.csv` with `.meta.json`, aborts naming both paths when it is absent, parses it with `JSON.parse`, and validates it against the explicit field allowlist in this plan's `<interfaces>` section. Build the returned `SidecarMeta` by reading each allowed key individually into a fresh object literal; never spread the parsed value, and never use a deep merge, so a `__proto__` or `constructor` key in the file cannot reach a compiler-owned object (threat T-02-01). Derive the scope from the raw filename's stem up to the first `-`, upper-case it, and abort when it fails `SCOPE_PATTERN` (threat T-02-03). `parseCanonicalCsv(text)` splits on newline, tolerates a trailing newline and `\r\n` line endings, requires the header line, and validates every data line as described in `<behavior>`. Do not add a CSV library: the canonical schema has no quoting and no embedded commas, per RESEARCH.md's "Alternatives Considered". `loadRawInputs(rawDir)` reads the directory, pairs every `.csv` with its sidecar, and returns them sorted by scope then kind.

`calendar.ts` implements Pattern 2. `deriveCalendar(inputs)` selects the input with `seriesKind` of `price` that has the earliest first date and the greatest row count, and builds the reference `Int32Array` from that series' own dates in ascending order. It does not consult a holiday-rule library and does not synthesize a date that no input carries: RESEARCH.md Pattern 2 records that the New York exchange's ad hoc Saturday closures in 1919, 1928, 1929 and 1933 appear only in the data, never in a rule. `toDaysSinceEpoch(iso)` parses with `Date.UTC` on the three integer components and divides by 86400000, so the result is time-zone independent. `indexOfDate` is a binary search returning `-1` when absent.
