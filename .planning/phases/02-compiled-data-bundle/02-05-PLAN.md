### The two new budget rows

`PerfBudget` gains a required field `unit` of type `BudgetUnit`, the union `'ms' | 'bytes'`. Every one of the eleven existing entries gets `unit: 'ms'`. The field names `thresholdMs` and `anchorMs` keep their current names: renaming them would touch `MeasurementRow`, `checkBudget`, `assertWithinBudget`, `renderTable`, `assertRunInvariants`, all three existing bench files, the self-test fixture and the over-budget self-test fixture, for no behavioural gain. The `unit` field is authoritative for how the number is read; the field name's suffix is historical. Say so in the interface's doc comment.

| Budget id | requirementId | unit | thresholdMs | anchorMs | anchorLabel | implementedInPhase |
|---|---|---|---|---|---|---|
| `DATA-BUNDLE-BYTES` | `PERF-08` | `bytes` | `1125000` | `1125000` | `900ms of PERF-08b at the declared 10 Mbps connection` | 2 |
| `DATA-BUNDLE-DECODE` | `PERF-08` | `ms` | `100` | `100` | `feels instant` | 2 |

Both rows reuse the existing `requirementId` value `PERF-08`, so `RequirementId` gains no member, the compile-time exhaustiveness check at the bottom of `perf-budgets.ts` still passes unchanged, and the self-test's eight-element requirement-id array is untouched. RESEARCH.md's Pitfall 2 is exactly the trap this avoids. Only the entry count changes, from eleven to thirteen.

Derivation of the byte threshold, recorded in the entry's `description` so it is not an arbitrary round number:

- `DECLARED_CONNECTION_BYTES_PER_SEC` is `1_250_000`, that is 10 Mbps. This is a deliberately conservative "typical broadband" floor that also covers poor mobile, chosen so the budget is meaningful rather than comfortable.
- PERF-08b's 1000ms covers data load and first render. `DATA-BUNDLE-DECODE` carves 100ms out of it for decode, leaving 900ms as the transfer share.
- 900ms times 1,250,000 bytes per second is 1,125,000 bytes.

The measured value for `DATA-BUNDLE-BYTES` is the sum of the brotli-compressed byte length of every file the compiler emits into the output directory, since that is what an edge actually transfers. Compression is performed with Node's built-in `zlib.brotliCompressSync` at its default settings, which is deterministic and needs no dependency.

### Unit awareness in `bench/report.ts`

Three changes, each small and each necessary:

1. `renderTable` appends the row's unit rather than a hardcoded `ms`, read from `PERF_BUDGETS[row.budgetId].unit`.
2. `assertRunInvariants`'s score-coherence check skips any row whose budget unit is not `'ms'`. A byte count is not divided by a calibration score, so `normalizedMs` equals `measuredMs` for such a row, and on any machine whose score is not exactly 1.0 the existing coherence check would fail it. This is a genuine landmine, not a cosmetic one.
3. Nothing else changes. `checkBudget` still performs the one numeric comparison, `assertWithinBudget` is still the per-file delegate, and `assertRunInvariants`'s verdict check is still the authoritative gate. Do not add a parallel assertion path for the new rows.

`bench/report.ts` is imported by browser-context test files, so it must not import a Node builtin. The brotli measurement therefore lives in `bench/bundle-bytes.ts`, a Node-only module imported by `vitest.config.ts`, following the same separation `bench/environment-store.ts` and `bench/accumulator-store.ts` already use.

### New browser-to-Node command

`vitest.config.ts`'s bench project gains one command alongside the existing five: `readBundleBytes`, returning `BundleBytes` as `{ files: string[], rawBytes: number, compressedBytes: number }`, implemented by calling `measureBundleBytes` from `bench/bundle-bytes.ts`. This mirrors `readCalibration` exactly: a browser-context test asks the Node process for a filesystem fact.

### Generated pointer module

`src/data-bundle.generated.ts` is written by `compileBundle` on every run and committed. It exports `MANIFEST_PATH`, the browser-reachable path to the content-hashed manifest such as `/data/manifest.<hash>.json`, and `BUNDLE_VERSION`. It is deterministic, carries a header comment naming the command that regenerates it, and is what keeps `index.html` the only uncached document under D-22: the manifest url is compiled into the JavaScript bundle rather than fetched from a fixed unhashed path.
