## User story

**As a** developer refreshing the bundled data, **I want to** run one command that pulls every equity and ETF series from a vendor that actually carries it, reconstructs total return from dividend events rather than from a back-adjusted column, and refuses to finish when the reconstruction disagrees with the vendor or when a manually-supplied file has gone stale, **so that** a refresh produces a reviewable git diff instead of a silent rewrite of every past number.

<assumption_delta_decision>
**Signal:** pluralization. The equity source went from one vendor to four, and `SourceSpec` acquired a second and a third vendor file format alongside FRED's CSV.

**Noun that is now primary:** the **fetch route**, not the vendor. The previous table encoded route as `manual: boolean`, a two-valued field that cannot express the vendor whose data this script fetches live on a developer machine and reads from disk on a shared-IP runner (D-27).

**Decision: promote.** `manual: boolean` is replaced by `route: FetchRoute`, the union `'live' | 'live-with-manual-fallback' | 'manual-only'`. Rationale: keeping the boolean and adding a second boolean beside it would make four states representable, two of which are nonsense, and every consumer would have to know which combination means what. A three-member union makes the illegal states unrepresentable and gives the route reporting D-27 requires one field to read.

**What would force a later change:** a fifth vendor whose route is neither fully live nor fully manual, for example one requiring a per-run credential. That would be a fourth union member, not a return to booleans.

**Suggested (not required) invariant test:** assert over `SOURCES` and `RATE_SOURCES` that every spec whose route is not `'live'` carries a non-empty `manualFile` and a positive `maxStalenessDays`, and that every spec whose route is `'live'` carries neither. That encodes the generalized intent rather than checking the current four vendors by name.
</assumption_delta_decision>

### Yahoo chart JSON shape

`chart.result[0]` carries `meta`, `timestamp`, `events` and `indicators`. Prices live at `indicators.quote[0].close`; the back-adjusted series lives at `indicators.adjclose[0].adjclose`. `events.dividends` and `events.splits` are objects keyed by the event's own unix timestamp, whose values carry `{ amount, date }` and `{ date, numerator, denominator, splitRatio }` respectively.

Bar timestamps are seconds since epoch at the session open, measured as 13:30 or 14:30 UTC across every file. Converting with `America/New_York` and converting with UTC agree on every bar of every file today, which is exactly why the conversion must be written against `America/New_York` explicitly: the agreement is a coincidence of the session open never crossing midnight UTC, not a property to rely on.

### Yahoo request URL

`https://query1.finance.yahoo.com/v8/finance/chart/<encoded symbol>?period1=<vendorPeriod1>&period2=<now>&interval=1d&events=div%2Csplit`

`<now>` is the current unix time computed at request time, never a far-future sentinel: a sentinel far past the present can trip the vendor's own hundred-year range rule. `vendorPeriod1` is `-2208988800` for `^GSPC` and `0` for every other symbol. `02-CONTEXT.md` records that the wide value succeeded for `^GSPC` and that the same value was rejected for another symbol with an explicit hundred-year-range error, so `0` is the safe default for anything whose history starts after 1970. Symbols beginning with a caret must be percent-encoded in the path.

### Total-return reconstruction (D-24)

`reconstructYahooTotalReturn(chart)` returns one canonical row per bar.

- Seed: the first row's value is the first bar's raw close. It is **not** the first bar's adjusted close. The adjusted series is back-adjusted, so its first element moves every time a new dividend is published, and seeding from it would rewrite the entire stored series on every refresh, which is the exact failure D-24 exists to prevent. A raw first-bar close never moves.
- Recurrence for every later bar: the previous level multiplied by the sum of this bar's close and this bar's dividend amount, divided by the previous bar's close. The dividend amount is zero on a bar with no dividend event and the summed amount when a bar carries more than one.
- Splits are not handled separately. The vendor's close and its dividend amounts are both already split-adjusted; an unhandled split would introduce a step of two times or more, and the D-25 gate holding under one part in a thousand for the eight-split and five-split symbols is the standing proof that they are. Say this in the function's doc comment so nobody later adds a second split adjustment on top.
- A dividend event whose date matches no bar aborts naming the symbol and the date. It matched on every symbol in the committed set, so a future mismatch is a real vendor change and not an expected condition to filter away.

### The D-25 reconstruction gate

`measureReconstructionDrift(chart, reconstructedRows)` compares growth paths rather than levels, so the seed choice above does not enter the comparison. For each bar after the first it computes the reconstructed level divided by the reconstructed first level, compares it against the adjusted close divided by the first adjusted close, and takes the absolute relative difference. It returns the maximum such value and the date it occurred on.

`MAX_RECONSTRUCTION_DRIFT` is `0.005`, that is one half of one percent.

Derivation, from measurements taken during planning over each symbol's full committed history:

| Symbol | Max drift over the whole path | Drift at the final bar | Growth over the history |
|---|---|---|---|
| EEM | 0.17642% | 0.11287% | 9.4x |
| QLD | 0.16916% | 0.14374% | 95.4x |
| EFA | 0.11790% | 0.00377% | 5.0x |
| TQQQ | 0.09269% | 0.08279% | 372.0x |
| TLT | 0.04412% | 0.01502% | 2.3x |
| VTI | 0.04214% | 0.01470% | 10.7x |
| SSO | 0.04178% | 0.02177% | 19.7x |
| UPRO | 0.03783% | 0.00797% | 137.0x |
| QQQ | 0.01810% | 0.00328% | 17.0x |

The final-bar column reproduces the five figures `02-CONTEXT.md` records under D-24 (QQQ 0.0033%, UPRO 0.0080%, VTI 0.0147%, TLT 0.0150%, TQQQ 0.0828%) to five decimal places, which is what confirms the recurrence above is the one those figures were measured with. The gate uses the max-over-path column because it is strictly the stronger statistic: the recurrence is multiplicative, so an error introduced at any bar persists as a permanent relative factor, and the maximum catches it wherever it happens.

`0.005` is 2.8 times the measured worst case of 0.17642%. The residual is float rounding in the vendor's own adjustment factors and it grows with cumulative growth, which is why the two most levered histories sit highest. That headroom absorbs several further years of compounding without a spurious failure while staying two orders of magnitude below the defect class the gate exists for: a missed or mis-scaled split moves the path by one hundred percent or more, and a dropped dividend introduces a permanent relative step equal to that dividend's yield.

State honestly in the doc comment what the gate does not catch. The smallest single dividend in this universe is 0.0059% of price (QLD, 2017-06-21), well below the noise floor, so this is not a per-dividend audit. It is a check that the reconstruction and the vendor still agree about the shape of the whole history.

### The D-27 fetch route and staleness gate

`resolveSource(spec)` returns the raw text plus which route produced it.

- `'live'` (the four FRED specs): fetch over https. A failure is a hard error with no fallback, exactly as today.
- `'live-with-manual-fallback'` (every Yahoo spec): attempt the fetch. On any failure, including a non-200 status, read `raw/manual/<manualFile>` instead and record that the manual path was taken. A missing manual file after a failed fetch is reported through the existing missing-source path.
- `'manual-only'` (Nasdaq and Shiller): read `raw/manual/<manualFile>`. A missing file is reported through the existing missing-source path.

`checkManualStaleness(spec, rows, today)` measures the age of the **newest observation in the data**, not the file's modification time. A modification time does not survive a git clone, so a mtime-based gate would report every freshly cloned repository as pristine and defeat the check for exactly the reader D-01 exists to serve. It returns a halt message when the age in calendar days exceeds `spec.maxStalenessDays`.

Declared thresholds:

- `10` for every daily manually-supplied source. The longest legitimate gap between consecutive United States equity trading bars is four calendar days, a Friday close followed by a Monday holiday reopening Tuesday. Ten days is two and a half times that, and short enough that a stale bundle cannot ship unnoticed for a fortnight. Measured today: the Yahoo files' newest bar is 2026-08-17, age zero.
- `75` for the Shiller monthly dividend input. Shiller publishes monthly with a lag; the committed file's newest anchor is 2026-08-01, age sixteen days. Seventy-five days allows one full missed publication cycle plus the normal lag while still catching a file two months out of date.
- No threshold for a `'live'` spec: it is refetched on every run by definition.

Reporting: the coverage table gains a route column printing `live` or `manual` per stem, and the run prints one summary line counting each. The sidecar's `retrievedAt` is the run date for a live-route series and the **newest observation's date** for a manually-supplied one, because writing the run date onto a stale manual file is precisely the trap D-27 warns the fallback must not become. `SidecarMeta` gains no new key, so `tools/bundle-compiler/src/raw-input.ts` and its strict allowed-key list are untouched by this plan.

### Untrusted-input discipline

Vendor JSON and vendor CSV are untrusted input crossing into a build script that writes files. Build every returned object key by key into a fresh literal; never spread parsed JSON and never deep-merge it, matching the discipline `loadSidecarOrThrow` already documents. Preserve every transport property plan 02-03 established: https only, manual redirect handling with a non-https redirect target rejected before any body is read, a non-200 status throwing with the url and the status named, and the streaming byte cap aborting mid-stream rather than after full buffering.
