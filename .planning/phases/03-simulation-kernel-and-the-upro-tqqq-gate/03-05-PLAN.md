    - The same 10,000 calls produce a final value identical to the first call's, proving the buffers are genuinely reused rather than reallocated.

the pool's worker processes, so `npm run test` continues to be the single command that runs this

that pool. Leave the `bench` and `bench-selftest` projects untouched.

Create `tests/kernel/allocation.test.ts`. Guard first: assert `typeof globalThis.gc === 'function'`
with a failure message naming both the `--expose-gc` flag and the `vitest.config.ts` `poolOptions`
entry that supplies it, so a future config regression names its own fix instead of silently
skipping the only SIM-11 evidence in the repo.

Build one 25,000-bar `KernelSeries` and one `KernelOutputs` outside the loop, using
`tests/kernel/fixtures.ts`'s builders with deterministic synthetic values (a fixed repeating return
pattern is sufficient; this is an allocation test, not a correctness test, and the correctness
suites already own that). Force a collection, record `process.memoryUsage().heapUsed`, run
`runBacktest` 10,000 times against the same buffers forcing a collection every 1,000 iterations,
force a final collection, and record `heapUsed` again. Assert the delta is below a named constant
tolerance in bytes, and put the tolerance's justification in a comment beside it: the kernel
returns one small result object per call, so 10,000 calls legitimately produce 10,000 short-lived
objects that the forced collections reclaim, and the tolerance covers the test harness's own
resident growth rather than the kernel's. Print the measured delta in the assertion message so a
regression reports its size.

Add the periodic-collection detail deliberately rather than only collecting at the ends: a single
before-and-after pair can pass while real garbage sits uncollected because V8's old-generation
collector prefers an idle thread, and this loop never idles.

Add the batch-flatness cross-check in the same file using `measureBatchedMinOfN` from
`bench/calibration.ts` at batch sizes 500 and 5000 over the same buffers, asserting the larger
batch's per-call time is at most 1.5x the smaller batch's. Record both figures in the assertion
message. This is the Node-side mirror of 03-RESEARCH.md's browser-side technique and needs no
browser, so it belongs in the `unit` project next to the heap-delta assertion.

Add a final assertion that the 10,000th call's `finalValue` equals the first call's, which fails
if any per-call state leaked into module scope.
