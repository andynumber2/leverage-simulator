  <behavior>
    - `computeTrackingError` over two identical return series returns 0 for both statistics.
    - Over two series differing by a constant per-bar amount `d`, the annualized tracking error is 0 (no dispersion in the difference) while the annualized drift is nonzero and has the sign of `d`.
    - Over two series whose differences have a known standard deviation `s`, the annualized tracking error equals `s * sqrt(252)` to within 1e-12 relative.
    - A window shorter than 2 bars throws a named error rather than returning NaN or Infinity.
    - Input arrays of unequal length throw naming both lengths.
    - A window's `years` is computed from the window's first and last calendar day numbers divided by 365.25, so the drift is annualized on elapsed calendar time rather than on a bar count.
  </behavior>
  <action>
Create `src/validation/tracking-error.ts` exporting `TrackingErrorWindow`
(`{ label: string; firstBar: number; lastBar: number; firstDayNumber: number; lastDayNumber: number }`),
`TrackingErrorResult` (`{ label: string; barCount: number; years: number;
annualizedTrackingError: number; annualizedReturnDrift: number; syntheticAnnualizedReturn: number;
referenceAnnualizedReturn: number }`), and three functions.

`annualizedTrackingError(syntheticReturns, referenceReturns, window)` implements D-11's Gate 1:
build the per-bar difference `syntheticReturns[k] - referenceReturns[k]` across the inclusive
window, take the sample standard deviation with an `n - 1` denominator, and multiply by
`Math.sqrt(252)`. Compute the mean in one pass and the sum of squared deviations in a second pass
rather than using the sum-of-squares shortcut, which loses precision when the mean is large
relative to the dispersion. Perform no rounding at any step.

`annualizedReturnDrift(syntheticValues, referenceValues, window)` implements D-11's Gate 2: take
each series' geometric annualized return over the window as `(last / first) ** (1 / years) - 1`
where `years` is `(window.lastDayNumber - window.firstDayNumber) / 365.25`, then return the
synthetic's minus the reference's. Annualizing on elapsed calendar days rather than on a bar count
is what makes the figure comparable across the full window and the two rate-regime sub-windows,
which contain different numbers of bars per year.

`computeTrackingError(syntheticValues, referenceValues, syntheticReturns, referenceReturns,
window)` returns a full `TrackingErrorResult` by calling both. It takes `Float64Array` arguments
and plain numbers only, imports nothing from the kernel, the data layer or the chart layer, and
assumes no test context: Phase 5's in-app view (VALID-04) and a CI data-change check are its other
two callers, and D-12 exists so there is exactly one implementation for all three.

Validate before computing: a window whose `lastBar - firstBar + 1` is below 2 throws naming the
window label and its bar count; arrays of unequal length throw naming both lengths; a non-finite
value anywhere in the window throws naming the offending index. These are the VALID-01 boundary
edge made explicit, and they exist so a data refresh that shortens an overlap fails loudly instead
of producing a NaN that propagates into a colour scale in Phase 7.

Create `tests/validation/tracking-error.test.ts` covering every behavior above against
hand-computed references built in the test, not against the bundle. Include the `s * sqrt(252)`
case with a series whose difference has an exactly known sample standard deviation, and assert
equality to within 1e-12 relative so the assertion pins the n-1 denominator rather than merely
the order of magnitude.
