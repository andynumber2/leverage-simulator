<objective>
The parameter column's first four controls: symbol with its dividend mode, entry date bounded live
by the strict tier, and a leverage slider that can be scrubbed. This is where the app stops showing
one fixed run and starts letting a person describe a real leveraged position.

Purpose: APP-01 and the single-control half of APP-04. D-10 draws the line this plan implements,
bounds a single control can resolve up front are enforced by the control, and D-12 fixes what
happens when a bound moves under a value that is already set: the date is explained, never moved.

Output: a pure bounds module, four parameter components, the eviction half of the validation
surface, and browser coverage of every state the UI-SPEC names for these three elements.
</objective>

Manifest facts verified this session against `public/data/manifest.f0a9dfbdfa.json`. Read them from
the manifest at runtime; the values below are for orientation, not for hard-coding.

- Series ids are `${SCOPE}/price-return` and `${SCOPE}/total-return`. The eleven selectable scopes
  are EEM, EFA, NDX, QLD, QQQ, SPX, SSO, TLT, TQQQ, UPRO, VTI. The `@rate` scope is the shared short
  rate and is not a selectable symbol; exclude it by its leading `@`.
- Every non-rate series carries `tiers: { strict: { firstDate, lastDate }, extended: { firstDate,
  lastDate } }`.
- `SPX/total-return` strict runs 1988-01-05 to 2026-08-14; `SPX/total-return` extended runs
  1927-12-30 to 2026-08-14. This is the widest strict-versus-extended gap in the bundle and is why
  D-09 pins strict until Phase 5 ships the bias disclosure.
- `NDX/price-return` runs from 1985-10-01 and `NDX/total-return` from 1999-03-04. That fourteen-year
  swing is the exact case D-12's live recompute and eviction copy exist for.

From `src/data/kernel-inputs.ts`: `buildKernelInputs` throws a named `Error` on an entry date outside
the selected series' supported range, naming the offending value and the supported range, and on a
holding period running past the last supported bar, naming the maximum bar count and the ending
date. Those thrown messages are the source of explanation text; catch and display them, do not
re-author equivalent copy.

From `src/app/state.ts` after plans 04-01 and 04-02: the `BacktestRequest`-shaped signal, the
`scale` signal, the load-status signal, `scheduleRun()`, and the derived metric values.

From `src/validation/cost-parameters.ts`: `COST_PARAMETERS` is a record whose entries each carry
`value`, `confidence` (`VERIFIED`, `CITED` or `ASSUMED`) and `citation`. `SourceCitation` renders
from those fields rather than from a hand-written string, so a citation cannot drift from the
constant it describes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input to kernel parameters | Free-form control input crosses into arithmetic the whole result rests on |
| Manifest data to control bounds | The bundle decides what is selectable, so a malformed manifest decides what a control offers |

|-----------|----------|-----------|----------|-------------|-----------------|

| T-04-19 | Information Disclosure | `ValidationExplanation` rendering a symbol or date derived from state | medium | mitigate | The message is rendered through Solid JSX text interpolation, which escapes by default; no `innerHTML` exists in `src/app`, asserted by a grep in this plan's acceptance criteria |
