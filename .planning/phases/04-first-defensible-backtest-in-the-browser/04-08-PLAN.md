From `public/data/`, the committed bundle measured this session: fourteen files totalling roughly
1.66MB, the largest single asset being `spx.4960dca187.bin` at 396,472 bytes. Workbox's default
`maximumFileSizeToCacheInBytes` is 2MB, so no single asset trips it, but the total precache size is
what the setting governs in practice; RESEARCH.md assumption A3 proposes 3,000,000 as a starting
value and states it must be confirmed against a real build listing rather than assumed. Confirm it.

`[data-theme="dark"]` override block already exist. This plan adds the resolution and switching
logic and the explicit canvas repaint, not the tokens.

From `src/app/components/ResultColumn/EquityCurveChart.tsx`: the chart already reads
`--color-accent` and `--color-text-muted` through `getComputedStyle` at render time. What is missing
is a trigger to re-read them when the theme changes.

From `perf-budgets.ts`: `DATA-BUNDLE-BYTES` budgets 1,125,000 bytes for the data transfer
specifically and is already measured and passing. Adding a service worker does not change what is
transferred on a cold load, so that row must stay green; if it moves, something about the build
changed that this plan did not intend.

From RESEARCH.md assumption A4: whether a partial uPlot update suffices for a theme repaint, or

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to third-party origin | Any outbound request leaves the user's machine with their argument in it |
| Service worker cache to app | Precached bytes are served without a network round trip and outlive a redeploy |
| CDN to browser | Cache-Control decides how long a stale artifact keeps being served |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Information Disclosure | The emitted `dist/` bundle | high | mitigate | `tests/app/static-build.test.ts` scans every emitted js, css and html file for an absolute external URL against an explicit reasoned allow-list, and fails naming the file and the URL; adding an external origin becomes a deliberate, reviewed test edit |
| T-04-32 | Tampering | Service-worker precache surviving a redeploy | medium | mitigate | Workbox's precache manifest is itself content-hash based, so a redeploy invalidates only what changed; `registerType` auto-update takes the new worker, and `decodeHeader(buffer, BUNDLE_VERSION)` still raises on a genuinely stale asset |
| T-04-33 | Tampering | `_headers` cache misconfiguration serving a stale shell | medium | mitigate | The two committed immutable rules cover only content-hashed paths; `index.html` and the generated worker get a short cache, asserted by the acceptance criteria checking both original rules survive verbatim |
| T-04-34 | Spoofing | Service worker precache poisoning on a compromised first load | low | accept | Out of this app's control surface; Cloudflare Pages serves over HTTPS by default and no app-specific control improves on that (RESEARCH.md Security Domain records the same disposition) |
| T-04-35 | Denial of Service (client) | A precache larger than the configured maximum silently skipping assets | medium | mitigate | Workbox fails at build time rather than at runtime when the maximum is too low, and the committed value carries a comment naming the measured total it was derived from |
</threat_model>
