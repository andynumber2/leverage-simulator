<objective>
Get the bench suite's own total runtime back inside `BENCH_TOTAL_RUNTIME_CAP_MS` on the baseline
host, aimed by the per-file attribution plan 07.1-01 recorded rather than by guessing which file is
expensive.

The starting figure is 43,259ms against a 30,000ms cap, from D-17 baseline run 32654061079. It has
never been the reported reason for a failed run: the verdict-fail gate fires first, which is what
plan 07.1-02 fixed. So this plan is where the breach actually gets closed.

Two honest complications, both stated up front rather than discovered mid-execution.

**First: this phase added cost before it removed any.** Plan 07.1-01's profiling arm and plan
07.1-04's contention arm are both new full-grid or near-full-grid work. They exist because criterion
1 required a measured breakdown and because the worker-count decision required interactivity
evidence that did not exist. Their one-time answers are now recorded in committed documents. What
remains is their standing cost on every future CI run, and there is no reason for that to be the
size it needed to be the first time. Task 1 gives each a declared budget and shrinks it to fit,
disclosing the scale factors, exactly the way 07-PERF-03-BASELINE.md's own
`REJECTED_POLYGON_BATCH_SIZE` reduction disclosed its batch size.

**Second: the tuning this phase landed may not, on its own, cover the gap.** Plans 07.1-03 and
07.1-04 reduce sweep cost, which reduces the runtime of every sweep-bearing arm. Whether the sum of
those savings plus this plan's reductions reaches 13,000ms is not knowable at plan time. So this
plan carries a stop rule and an escalation path, and neither of them is "raise the cap".
`BENCH_TOTAL_RUNTIME_CAP_MS` is a run-level cap value; moving it in response to a measurement is
exactly what PERF-01a prohibits and what its own error message says requires a recorded decision
rather than a silent edit. If the suite still does not fit, plan 07.1-06 records that as a Key
Decision naming the remaining lever.

Purpose: repeat cost that has crept, removed where it actually is.
Output: a measurably shorter suite, with every reduction disclosed, or a recorded shortfall with a
named lever.
</objective>

`commands.recordMeasurement` is a gated recorder and its measured workload is off limits; an arm
that only records an info line is a reduction candidate.

Apply, in this order, stopping as soon as the projected baseline total fits inside 30,000ms with at
least 3,000ms of margin:

  1. Remove, do not merely shrink, any informational arm that re-measures a path the project has
     already REJECTED and whose historical figure is already transcribed in a committed document.
     Repeating such a measurement on every CI run buys nothing: the decision it informed is closed
     and the number is recoverable. When you remove one, state in the file's header which committed
     documents carry the figure, so the evidence trail survives the arm.
  2. Reduce the repeat or batch count of any remaining informational arm, keeping every timed unit
     above `MIN_MEASUREMENT_MS` with real margin rather than a marginal fit, and updating the arm's
     own recorded line so it discloses the count it actually ran at. This is exactly the
     `REJECTED_POLYGON_BATCH_SIZE` precedent.
  3. Reduce setup cost that is shared by a gated arm without changing what that arm measures: a
     bundle loaded twice in one file, a build performed that a prior file already performed, a
     fixture rebuilt per test that could be built once per file. This changes no measured workload
     at all and is therefore the safest lever, but it is listed third because it is usually the
     smallest.

Do not reduce `INTERACTION_DRAG_STEP_COUNT` unless steps 1 through 3 are exhausted and the suite

how many input events land per animation frame, which means D-03's coalescing claim stays testable.

maximum-recompute figures are maxima over, and a maximum over a smaller sample is a weaker gate.
Both PERF-07a and PERF-07b are gated `MeasurementRow`s. If you make this cut, disclose the new step
count in both arms' recorded info lines and state the weakened-sample tradeoff in the plan summary,
