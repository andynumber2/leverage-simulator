## Sampling Rate

- **After every task commit:** `npm run bench -- --reporter=verbose`
- **After every plan wave:** `npm run test && npm run bench`
- **Before `/gsd-verify-work`:** full suite green locally, and **two consecutive** real D-17
  baseline CI runs showing `verdict=pass` for the headline PERF-03 row. User decision,
  2026-08-23: a single normalized figure carries roughly +/-13% at 2 sigma (WINDOWS.md entry
  #2, 6.36% relative residual over 13 recorded D-17 runs), so one thin pass is not evidence
  the budget is met. This mirrors how the D-20 escalation was established in the first place:
  crossed on three consecutive runs, not asserted from one
- **Max feedback latency:** ~60s local; a CI baseline run is minutes, not seconds, so it is a
  wave-boundary gate rather than a per-task one

## Wave 0 Requirements

Every Wave 0 gap is assigned to a wave-1 or wave-2 task. None is left to be discovered mid-phase.

- [ ] A diagnostic-only profiling bench arm (`recordInfoLine` only, no `MeasurementRow`) for
      success criterion 1's attributed breakdown: worker startup, chunk dispatch and transfer,
      per-cell kernel time, idle time at `workerCount=3`.
      **Closed by:** plan 07.1-01, Task 1 (`bench/sweep-pool-profile.bench.test.ts`), wave 1.
      Extended beyond the original gap to also cover the `solveIrr` branch, its measured
      cash-flow count per cell and its measured npv-evaluations-per-solve ratio, per
      07.1-RESEARCH.md Open Question 3.
- [ ] New `assertRunInvariants` test cases asserting a verdict-fail and a runtime-cap breach are
      both reported when both are true (success criterion 5).
      **Closed by:** plan 07.1-02, Task 1 (`bench/report.ts`, `tests/report.test.ts`), wave 1.
- [ ] A concurrent-drag-during-sweep bench arm, since no existing bench exercises interaction
      against an in-flight sweep.
      **Closed by:** plan 07.1-04, Task 1 (`bench/sweep-contention.bench.test.ts`), wave 2.
      Built unconditionally rather than only if `workerCount=4` is pursued: the worker-count
      decision cannot be made without it, and its absence is itself the finding 07.1-RESEARCH.md's
      Pitfall 3 names. Implemented as an in-page frame-sampling arm driving the real `runBacktest`
      against a real resolved series while a real full-grid sweep is in flight, not as a Playwright
      pointer drag. That choice is cheaper and directly comparable with PERF-07a's 50ms ceiling and
      PERF-07b's 16ms budget, and its limitation (it drives no UI, so Solid's reactive path and the
      browser's paint are outside its window) is recorded in the arm's own header and carried into
      the manual check below.
- [ ] A structural exactly-once column-coverage proof for `partitionColumns`, added during planning
      rather than seeded by research: the 50-cell coprime-stride equality sample cannot catch a
      partition that skips or double-counts a column, and plan 07.1-04 changes the partition shape.
      **Closed by:** plan 07.1-02, Task 2 (`tests/sweep/partition.test.ts`), wave 1, before any
      plan in this phase changes that shape.
