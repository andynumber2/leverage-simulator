## Pattern Assignments

### `src/sweep/sweep-pool.ts` (modify)

**Shape to respect (this file, not an external analog):**

- `workerCountForCores` at lines 47-50 is a one-line pure function, deliberately re-declared
  here rather than imported from `bench/` (see its own doc comment). Any change to the
  `cores - 1` rule stays a one-line edit to this function; do not restructure its signature.
  ```typescript
  // src/sweep/sweep-pool.ts:47-50
  export function workerCountForCores(cores: number): number {
    return Math.max(1, cores - 1)
  }
  ```
- `CHUNKS_PER_WORKER = 4` (line ~40) and `partitionColumns` (lines ~117-139) are the chunk-shape
  levers. `partitionColumns` is a pure function taking `entryDates` + `workerCount`, returning
  contiguous column ranges — any load-balancing change must preserve "every column belongs to
  exactly one chunk" (Pitfall 1 in RESEARCH.md) and stay pure/testable the same way.
- Dispatch loop (`drainQueue`, lines ~340-401) already does: `Comlink.transfer` both directions,
  a `Promise.race` against a per-chunk timeout, and routes both success and failure paths through
  `mergeChunkResult`'s generation-gated merge. Any tuning here (e.g. `workerCount=4`) must not
  bypass this merge/timeout structure.
- Doc-comment convention: every non-trivial function has a block comment citing the originating
  plan/task and reasoning, not just a one-line description. Follow this for any new function.

### `src/sweep/sweep.worker.ts` (modify)

**Shape to respect:**

- `computeChunkMetrics` (lines ~167-249) is the one-pass per-chunk body: for each column, resolve
  `KernelSeries` once (`resolveColumnSeries`), then loop rows calling `runBacktest` once per row,
  then compute `multiples`/`drawdowns`/`annualized`/`flags` from the SAME `result` — never a
  second `runBacktest` call per cell (METR-06). The D-24 branch (`useIrr` ternary, lines ~225-229)
  is resolved once per sweep from `request.params`, not per cell:
  ```typescript
  // src/sweep/sweep.worker.ts:225-229
  const annualizedValue = useIrr
    ? solveIrr(buildCashFlows(kernelParams, resolution, outputs, result, scratchCashFlows))
    : solveCagr(kernelParams.initialInvestment, result.finalValue, calendarDays)
  annualized[cell] = annualizedValue === null ? ANNUALIZED_UNDEFINED : annualizedValue
  ```
  Any profiling instrumentation added here (Pattern 2 in RESEARCH.md) must not sit inside this
  loop in a way that changes what `bench/sweep.bench.test.ts`'s gated PERF-03 row measures —
  keep it in a separate diagnostic call path (e.g. a second exported function, or a debug-gated
  flag), per RESEARCH.md's own recommendation.
- `computeChunkMetrics` is a plain, synchronous, Comlink-free exported function specifically so it
  is unit-testable without a Worker (`tests/sweep/metrics-one-pass.test.ts`). Preserve this: do
  not fold timing calls into it in a way that requires a browser context to run.
- `Comlink.expose` guard at the bottom (`if (typeof self !== 'undefined')`) — required for any
  new Worker-side code that must also stay importable from the Node `unit` project.

### `bench/report.ts` — `assertRunInvariants` (modify)

**Shape to respect:** sequential `if (...) throw` gates, each with a comment explaining why it is
ordered where it is relative to its neighbors (verdict-fail, then PERF-08 coverage, then score
coherence + PERF-03 host-width guard, then runtime cap). The fix (collect verdict-fail AND
runtime-cap violations, throw once with both) must preserve this ordering convention and every
existing gate's message text (tests assert on regex substrings, not full-string equality):

```typescript
// bench/report.ts:383-389 (verdict-fail gate, first)
const failing = rows.filter((r) => r.verdict === 'fail')
if (failing.length > 0) {
  const failingIds = failing.map((r) => r.budgetId).sort((a, b) => a.localeCompare(b))
  throw new Error(
    `assertRunInvariants: ${failing.length} row(s) failed budget: ${failingIds.join(', ')}`,
  )
}
```
```typescript
// bench/report.ts:479-485 (runtime-cap gate, last)
if (totalRuntimeMs > BENCH_TOTAL_RUNTIME_CAP_MS) {
  throw new Error(
    `assertRunInvariants: total bench runtime ${totalRuntimeMs}ms exceeds the declared cap ` +
      `of ${BENCH_TOTAL_RUNTIME_CAP_MS}ms (D-08): repeat cost has crept; raising the cap ` +
      'requires a recorded decision, not a silent edit',
  )
}
```
RESEARCH.md's own illustrative combined-violation shape (`violations: string[]`, pushed to and
joined with `'; '`) is the recommended replacement for these two specific gates only — leave the
PERF-08-coverage, score-coherence, and PERF-03 host-width guards exactly as they are, each still
its own early `throw`.

### `tests/report.test.ts` (extend for Success Criterion 5)

**Shape to respect:** every existing `describe('assertRunInvariants...')` block builds a row
fixture (e.g. `fullRowSet`, `withFailure`) then asserts with `.toThrow(/regex/)` chained calls,
one call per expected substring:

```typescript
// tests/report.test.ts:191-192
expect(() => assertRunInvariants(withFailure, 500)).toThrow(/PERF-05/)
expect(() => assertRunInvariants(withFailure, 500)).toThrow(/failed budget/i)
```
```typescript
// tests/report.test.ts:170
expect(() => assertRunInvariants(fullRowSet, BENCH_TOTAL_RUNTIME_CAP_MS + 1)).toThrow(/exceeds/i)
```
The new combined-violation test case should build a row set with one `verdict: 'fail'` row (like
`withFailure`) and pass a `totalRuntimeMs` above `BENCH_TOTAL_RUNTIME_CAP_MS` (like the exceeds
case), then assert `.toThrow(/failed budget/i)` AND `.toThrow(/exceeds/i)` in the same block —
proving both substrings survive in one thrown message, not that either alone still works.

### Bench measurement five-step shape (gated rows)
**Source:** `bench/sweep.bench.test.ts:340-413`, `bench/perf-07.bench.test.ts` header
**Apply to:** any bench arm that DOES produce a gated `MeasurementRow` (not the two CREATE files
above, which are informational-only).
```typescript
const score = await resolveRunCalibration()
const rawMs = await measureMinOfN(REPEAT_COUNT, async () => { /* work */ })
const normalizedMs = normalize(rawMs, score)
await commands.recordEnvironment(captureEnvironment(score))
const row: MeasurementRow = { budgetId, requirementId, measuredMs: rawMs, normalizedMs, ... }
await commands.recordMeasurement(row)
expect(() => assertWithinBudget(row)).not.toThrow()
```

### Correctness-before-timing discipline
**Source:** `bench/sweep.bench.test.ts` tests 1-3 (lines ~278-330), Pitfall 1 in RESEARCH.md
**Apply to:** any change to `partitionColumns`/`workerCount`/chunk shape in `sweep-pool.ts`.
Re-run the existing 10,000-finite-cells-no-holes test and the 50-cell coprime-stride
pool-vs-serial equality test (`SERIAL_REFERENCE_STRIDE=197`) unmodified — they already call
whatever `pool` was constructed with, so they re-validate any shape change without needing a new
test.
