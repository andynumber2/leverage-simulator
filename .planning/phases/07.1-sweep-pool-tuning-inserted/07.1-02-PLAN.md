<objective>
Put both anti-regression clamps in place BEFORE any tuning lands, so no later plan in this phase
can pass through a hole.

Clamp one is criterion 5's second half. `assertRunInvariants` currently throws on the first failing
check, and the verdict-fail gate runs before the runtime-cap gate. CI run 32654061079 had both: a
PERF-03 verdict of `fail` at 1168.59ms and a `totalRuntimeMs` of 43,259ms against a 30,000ms cap.
Only the first was ever reported. 07-VERIFICATION.md carried the cap breach forward as an
observation precisely because it never became the reported reason. The fix collects the two
violations and throws once with both. It does not reorder which check wins: reordering would just
flip which one gets masked.

Clamp two is criterion 6's sampling hole. The pool-versus-serial equality check in
`bench/sweep.bench.test.ts` samples 50 cells on a coprime stride, not the full 10,000-cell grid
(a deliberate Phase 1 cost decision, recorded in STATE.md). That sample is sufficient to catch a
partitioning bug that corrupts values, but it is not sufficient to catch a partition that skips or
double-counts a column: a 50-cell stride can miss the affected columns entirely, and every written
cell stays finite either way, so the 10,000-finite-cells-no-holes test does not catch it either.
Plan 07.1-04 changes the partition shape (12 chunks become 16 if the worker count moves), so this
hole must be closed first, structurally, not by sampling harder.

Purpose: a faster wrong answer must not be able to pass as an improvement, and a runtime-cap breach
must not be able to hide behind a budget failure.
Output: a combined-violation `assertRunInvariants`, and a structural proof that every column belongs
to exactly one chunk.
</objective>
