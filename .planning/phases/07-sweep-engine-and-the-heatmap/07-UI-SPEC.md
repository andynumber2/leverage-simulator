# Phase 7: UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope note: read before using this document

This phase ships the heatmap and its surrounding interaction (mode switch, marginal slice
charts, metric toggle, hover/crosshair/drill-down, caption strip). It does **not** re-decide the
value-to-color mapping, the ruin/incomplete categorical rules, or the diverging-ramp palette:
those are already fixed at implementable precision in `06-HEATMAP-SPEC.md` (§3-§8) and this
document defers to it rather than repeating its numbers. This document's job is the surface area
`06-HEATMAP-SPEC.md` explicitly leaves open for Phase 7 (§11: sweep mode, metric toggle, ruin
under hold-to-today, pan/zoom, progressive paint, the hover question) plus the DOM chrome (mode
switch, toggles, legend adaptation, caption strip, hover readout) that has no precedent yet.

All spacing, typography, and base color tokens are reused unchanged from `04-UI-SPEC.md` and
`06-UI-SPEC.md` — this document states the reuse once per section and then adds only what is new.

## Spacing Scale

Reused unchanged from `04-UI-SPEC.md`/`06-UI-SPEC.md` (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | Gap between a legend tick mark and its numeric label (unchanged from Phase 6); gap between rows inside the hover readout card |
| sm | 8px | Gap between the legend ramp and the two detached categorical swatches (unchanged); padding inside the hover readout card; gap between the heatmap canvas and each marginal slice chart (D-16 — the slices read as structurally attached to the field, not as separate panels) |
| md | 16px | Gap between the mode switch (D-15) and the heatmap panel below it; gap between the grid/slice-chart block and the caption strip (D-30); gap between the caption strip and the legend, unchanged from Phase 6's D-21 placement |
| lg | 24px | Outer padding of the sweep-mode result-column panel, matching Phase 4's result-column outer padding |
| xl | 32px | Not used within the sweep panel; reserved for the column-level gap already defined in `04-UI-SPEC.md` |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- The heatmap canvas and its two marginal slice charts (D-16) sit at `sm` (8px), not `md`, specifically so the three read as one instrument rather than three separate cards — this is the same "the reader sees the 2D field and both 1D cuts as one picture" intent D-16 states.
- The hover readout card (D-19/D-20) is a small floating overlay, not a layout element: it uses `sm` padding throughout and does not participate in the panel's outer spacing rhythm.
- Per-form display geometry, cell size, and hatch stroke geometry remain out of this scale's scope, per `06-UI-SPEC.md`'s identical exception — those are `06-HEATMAP-SPEC.md` §4/§7 values, unchanged by this phase.

### New this phase: the sequential ramp for max drawdown (D-25)

Max drawdown has no meaningful midpoint (PITFALLS E1), so it is never rendered through the
diverging blue-orange ramp `06-HEATMAP-SPEC.md` §3 defines. It needs its own family, distinct
enough from the diverging ramp's blue/orange hues that a reader never mistakes one scale for the
other when the metric toggle changes, and distinct from the destructive red reserved for ruin.

| Property | Value |
|---|---|
| Scale type | Sequential, no midpoint, no diverging center |
| Transform | Linear (magnitude, not log — a percentage drawdown does not span orders of magnitude the way a return multiple does) |
| Domain (fixed) | `0%` to `80%`, clipped beyond, never fitted per sweep, following the same fixed-domain discipline as `06-HEATMAP-SPEC.md` §3's `DOMAIN_LOG_MIN/MAX` |
| Interpolation space | Oklab, piecewise-linear between stops, same mechanism `interpolateRamp` already uses — implemented as a second stops array and a second exported interpolator (or a parameterized `interpolateRamp`), per Research Pattern 6; the existing diverging call sites are not changed |
| Palette family | Single-hue, light-to-dark violet — chosen specifically because neither blue nor orange (used by the diverging scale) nor red (reserved for ruin) nor green (excluded project-wide per PITFALLS E3's red-green ban) is available |

`SEQUENTIAL_RAMP_STOPS` (recommended values, must still clear VIZ-07's perceptual-uniformity
ratio via the same measured-step-ratio test the diverging ramp passes — the values below are a
reasoned default, not exempt from that test):

| `t` | hex | Meaning |
|---|---|---|
| 0.0 | `#EEEBFB` | 0% drawdown |
| 0.33 | `#B7A9EA` | ~27% drawdown |
| 0.67 | `#7857C4` | ~53% drawdown |
| 1.0 | `#3B1B7E` | 80% drawdown and above (clipped) |

Legend ticks: `0%`, `20%`, `40%`, `60%`, `"80% and above"` (clipped label, matching the
convention `06-HEATMAP-SPEC.md` §5 already uses for `"0.01x and below"`/`"100.00x and above"`).
No tick is emphasized — there is no breakeven-equivalent threshold to call out, unlike the
diverging ramp's bolded `1.00x` tick.

### New this phase: extended accent reservation

Accent stays reserved for exactly the elements `04-UI-SPEC.md` already lists, plus three new
uses this phase introduces. No other new element in this phase is accent-colored.

- The **committed crosshair** (D-19/D-22) and its axis guide lines, on click — solid, 2px.
- The **active segment** of the Single run / Sweep mode switch (D-15).
- The **active segment** of the metric toggle (D-23).

The **ghost crosshair** (D-19, hover-only, transient) deliberately does *not* use accent — it
uses Text muted at reduced visual weight (1px, dashed) specifically so it reads as provisional
and is never confused with the committed, accent-colored crosshair. This is the visual
distinction D-19 requires between the two crosshair states.

The **short-horizon boundary rule** (D-29) also does not use accent: it uses Text muted, 1px,
dashed, so it never competes with the breakeven contour (`var(--color-text)`, 2px, solid, per
`06-HEATMAP-SPEC.md` §7) or with the committed crosshair for visual priority, while still reading
as a deliberate marked boundary rather than incidental chrome.

## Visual Hierarchy

The heatmap field is the primary focal point of the sweep panel, unchanged from Phase 6's
established hierarchy. New elements introduced this phase rank as follows, in descending visual
weight:

1. **The heatmap field itself** (contour fill, breakeven line, ruin hatch) — primary.
2. **The committed crosshair and its axis guides** — secondary, accent-colored specifically so it
   is findable against the field without competing with the field's own color-coded content.
3. **The marginal slice charts** (D-16) — read as an extension of the field (same axis, `sm` gap),
   not a separate visual block.
4. **The mode switch and metric toggle** — controls, styled as controls, sit above the field and
   never inside it.
5. **The caption strip** (VIZ-04 statement + VIZ-10 caveat) — Body-size copy directly under the
   field, inside the eye path from field to legend, matching `06-HEATMAP-SPEC.md` §6's placement
   rule. Not decoration, not a footnote.
6. **The legend** — subordinate, below the caption strip.
7. **The ghost crosshair and hover readout** — lowest-weight, transient, must never obscure the
   cell the reader is currently pointing at (the readout is positioned to avoid the cursor's own
   position, e.g. offset above-right, flipping to avoid clipping at panel edges).
8. **The short-horizon boundary rule** (D-29) — a deliberately quiet marking, muted and dashed,
   that must still be legible in a cropped screenshot per its own requirement (VIZ-09), so "quiet"
   does not mean "faint to the point of missable" — verify at real contrast against the field
   colors on both sides of the boundary.

A treatment where the mode switch, metric toggle, or hover readout draws more visual attention
than the field itself fails this hierarchy.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable in sweep mode — no new user-initiated action button exists; "Copy link" (SHARE-01, unchanged from Phase 4) remains the app's one explicit action and now also encodes sweep state per D-04 |
| Empty state | Not applicable — a sweep always computes a real 10,000-cell field once its inputs resolve (D-03's grid is fixed); there is no zero-data sweep state to design. The nearest analog, first paint before the coarse pass resolves, is a **loading** consideration, covered below |
| Error state — sweep chunk failure | Not decided by `07-CONTEXT.md`; recommended default: a chunk that fails or times out (mirroring `bench/sweep-pool.ts`'s `chunkTimeoutMs` pattern) renders its cells with `INCOMPLETE_RGBA` (the same flat neutral grey already reserved for "no value here," since a failed cell genuinely carries no value) and the caption strip appends one line: `"{N} cells could not be computed. Try a different parameter."` This reuses an existing categorical treatment rather than inventing a third grey-adjacent state, and is flagged for checker review since it is a researcher default, not a locked decision |
| Destructive confirmation | Not applicable — no destructive action exists in sweep mode; ruin is a computed outcome, not a user action, and needs no confirmation, unchanged from Phase 4's identical reasoning |
| **Sweep-mode switch (D-15)** | Two segments: `"Single run"` / `"Sweep"` |
| **Metric toggle (D-23/D-24)** | Three segments: `"Multiple of contributed"` (default), `"Max drawdown"`, and the annualized segment labeled `"IRR"` when `backtestRequest().contributionAmount` is non-zero or `"CAGR"` when it is zero — mirroring `HoldingModeControl`'s pattern of a single control whose label text itself states which mode is active, never showing both labels at once |
| **VIZ-04 mode statement, fixed-period (D-27/D-30)** | `"Every cell held for {N} years."` where `{N}` is `holdingPeriodBars / 252`, rounded to one decimal, e.g. `"Every cell held for 10.0 years."` |
| **VIZ-04 mode statement, open-ended (D-27/D-30)** | `"Every cell held to end of data ({date})."` — reuses `HoldingModeControl`'s exact "end of data, not today" framing and its resolved `endOfDataDate`, never "today" |
| **VIZ-10 caveat (unchanged, `06-HEATMAP-SPEC.md` §6)** | `"The same market history, viewed from every possible starting point. Adjacent columns share nearly all their data, so this is a sensitivity analysis over one past, not 10,000 independent trials."` |
| **Legend, sequential ramp ticks (new, D-25)** | `0%`, `20%`, `40%`, `60%`, `"80% and above"` |
| **Legend, ruin/incomplete swatches (unchanged, `06-HEATMAP-SPEC.md` §5)** | `"Ruined: position reached zero"` / `"Holding period incomplete"` |
| **Short-horizon boundary rule label (D-29)** | `"Right of here: under 3 years held"` — the threshold is fixed at **3 years** (756 trading bars), stated in the label per D-29's explicit requirement that it be stated, not implied |
| **Hover readout field labels (D-20)** | `"Entry"`, `"Leverage"`, `"Multiple"`, `"Drawdown"`, and `"IRR"` or `"CAGR"` matching the active metric-toggle naming rule; a ruined or incomplete cell replaces the numeric multiple/drawdown/annualized rows with the categorical label itself (`"Ruined"` / `"Incomplete hold"`), never showing a stale or zeroed number beside the categorical state |
| **Drill-down affordance (D-22)** | No new copy — clicking a cell and switching to "Single run" is the entire mechanism; no tooltip or button text needs to explain it beyond the existing mode-switch labels |

## UI Considerations

Authored against the shape-rooted UI-consideration taxonomy (empty / loading / error / populated
/ partial / overflow / zero-one-many / long-text), following the same propose-then-confirm
discipline `04-UI-SPEC.md`/`06-UI-SPEC.md` used. Kinds are author-confirmed below rather than
left to a prose heuristic, since several of these elements (the crosshair, the canvas field
itself) are not ordinary form/list/nav shapes.

**Coverage: 8 elements, 34 applicable considerations, 26 resolved (18 explicit, 8 backstop), 8 dismissed with reason, 0 unresolved.**

### E1: SweepModeToggle (D-15)

_Kinds: interactive-control (confirmed)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| loading | ✅ explicit | Disabled with the rest of the parameter/result surface until the manifest decodes, identical to every other control's loading treatment in `04-UI-SPEC.md` |
| error | dismissed | A two-segment switch with no external dependency has no failure mode of its own to design |
| long-text | dismissed | Fixed two-word labels ("Single run" / "Sweep"), no variable-length content |

### E2: MetricToggle (D-23/D-24)

_Kinds: interactive-control (confirmed)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| loading | ✅ explicit | Disabled until the manifest decodes, same pattern as E1 |
| error | dismissed | No independent failure mode |
| populated | ✅ explicit | Always exactly three segments; the third segment's label text changes (IRR/CAGR) but the segment count never does, so there is no zero/one/many variance to design |
| long-text | 🧪 backstop | "Multiple of contributed" is the longest segment label in the app's control vocabulary; verify at the narrowest supported viewport that the three-segment control wraps or compresses rather than overflowing its column |

### E3: HeatmapPanel — the canvas field itself (VIZ-03, D-05/D-11/D-12)

_Kinds: media (confirmed)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | dismissed | The field always renders a complete grid once any pass resolves (D-12 forces a complete low-res field before any partial refinement); there is no partially-empty field state to design, by construction |
| loading | ✅ explicit | D-12's coarse-to-fine pass IS the loading treatment: a complete low-resolution contour paints within PERF-04's 100ms, then refines to the full grid, with no spinner, bar, or percentage (D-14) |
| error | ✅ explicit | Sweep chunk failure renders `INCOMPLETE_RGBA` for the affected cells plus the caption-strip line above; total pool/worker unavailability (e.g. `hardwareConcurrency` reporting 0 workers constructible) falls back to the field showing its previous complete state indefinitely with the same caption-strip line, never a blank canvas |
| populated | ✅ explicit | Typical volume is the full 200x50 = 10,000-cell field at `06-HEATMAP-SPEC.md` §7's Form 2 geometry, in one of three metric scales (diverging multiple/annualized or sequential drawdown) |
| partial | ✅ explicit | Mid-drag (D-32) or mid-cancellation (D-13), the field shows the previous sweep's complete result until the new sweep's own coarse pass replaces it whole — never a half-old/half-new blended field, and never an empty flash |
| overflow | 🧪 backstop | The field's fixed panel size (D-10: internal resolution gives, not panel size) must not force horizontal scroll or clip at the narrowest supported viewport; verify against the same narrow-viewport test class `04-UI-SPEC.md`'s E5 established |
| zero-one-many | dismissed | Grid dimensions are fixed at 200x50 (D-03); not a variable-count collection |
| long-text | dismissed | The field itself renders no text; axis tick labels are covered under E7 (legend/axis) below |

### E4: SliceChart x2 (VIZ-01/VIZ-02, D-16)

_Kinds: media (confirmed)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | dismissed | A slice chart always has data the moment the field has a complete pass (it is a direct read of one row/column of the same grid); there is no independent empty state |
| loading | ✅ explicit | Follows the field's own loading state exactly (E3) since both slices read the same cached grid — no separate spinner or skeleton |
| error | dismissed | Not an independently-fetched surface; any field-level error (E3) already applies uniformly to the row/column it reads |
| populated | ✅ explicit | 200 points (entry-date slice) or 50 points (leverage slice), rendered with `EquityCurveChart.tsx`'s existing uPlot destroy-and-recreate pattern, following `log-axis-splits.ts` where the slice's own value range needs a log axis |
| overflow | 🧪 backstop | Verify at the narrowest supported viewport that the vertical (leverage) slice chart's y-axis gutter, measured the same way `EquityCurveChart.tsx` measures its own, does not compress the shared leverage axis illegibly small |
| long-text | dismissed | Axis tick labels route through `src/metrics/format.ts`, bounded, no free text |

### E5: Hover readout + ghost/committed crosshair (D-19/D-20/D-21/D-22)

_Kinds: interactive-control (confirmed)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | ✅ explicit | Before any pointer interaction, neither crosshair nor readout renders — no reserved empty slot, matching the app's established "absent by default" pattern for conditional UI (`04-UI-SPEC.md` E9) |
| loading | dismissed | The readout only ever displays values already present in the cached grid; it has no independent fetch or compute step of its own |

| overflow | 🧪 backstop | Near the panel's right or bottom edge, the readout must flip to stay on-screen rather than clip; verify at the field's own corner cells |
| long-text | dismissed | All readout values route through the existing bounded formatters (`formatMultiple`, date, percentage); no free-length content |
