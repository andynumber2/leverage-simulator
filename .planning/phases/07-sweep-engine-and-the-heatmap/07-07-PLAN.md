**Vertical slice (VIZ-02), fixed entry date, sweeping leverage.** 50 data points, one COLUMN of the
cached grid, BESIDE the heatmap, sharing its leverage axis so the two line up row for row.
`07-UI-SPEC.md` section E4 names uPlot for both slices, but uPlot's independent variable is always
its x axis and it has no transpose: a chart whose independent variable runs up the y axis is not a
configuration of uPlot. Rotating a uPlot instance with a CSS transform would rotate its tick labels
with it. So render this one as a hand-rolled Canvas 2D polyline plus axis, reading its theme colours
through the same `getComputedStyle` rule and its leverage ticks through `integerLeverageTicks`, which
is already the heatmap's own leverage-axis tick source and is therefore guaranteed to agree with the
field's rows. Record this departure from E4's stated pattern, and its reason, in the component
header. Fifty points, one polyline, two axes: this is a small hand-rolled chart, not a second
charting integration.

**Breaks, not interpolation.** A slice crossing a cell flagged `CELL_FLAG_RUINED` or
`CELL_FLAG_INCOMPLETE`, or carrying `ANNUALIZED_UNDEFINED`, BREAKS the line at that point rather than
interpolating through it. uPlot renders a gap for a null value; the hand-rolled chart must start a
new subpath. Drawing a continuous line across a ruined cell would assert a value where there is none,
which is the same failure the field's categorical treatment exists to prevent.

**Coarse-pass behavior.** While only the coarse grid exists, both slices read the coarse grid and
refine in step with the field. Neither has its own spinner or skeleton, and neither has an
independent empty state: a slice always has data the moment the field has a complete pass.

**Layout.** Both charts sit at the 8px small spacing token from the field, not the 16px medium one,
specifically so the three read as one instrument rather than three cards. Mount both from
`HeatmapPanel.tsx`.

No em dash characters. Minimize ternaries and never nest them.
