  <behavior>
    - Given a monotonically increasing analytic field with no categorical cells, each band's rings are closed (first point equals last point) and the union of all bands' filled areas covers the whole field rectangle with no gap and no overlap, to within a stated numeric epsilon.
    - A band that runs off the side of the field is closed along the field rectangle's own edge, so its ring includes the corner points it needs and its area is not truncated at the last iso-segment.
    - A field with a bullseye pattern (a high-value island in the middle of a low-value field) produces, for the outer band, one outer ring plus one hole ring, and filling with the even-odd rule leaves the island unpainted by the outer band.
    - Every cell carrying `CELL_FLAG_RUINED` or `CELL_FLAG_INCOMPLETE` is excluded from every band polygon, so a categorical region is a hole in the field that no band fill covers.
    - A field of exactly one constant value produces one ring covering the whole field rectangle for that value's band, and empty ring lists for every other band.
    - A degenerate grid (`cols` below 2 or `rows` below 2) returns empty ring lists rather than throwing.
  </behavior>
  <action>
Create `src/heatmap/polygon-fill.ts` following its sibling modules' conventions exactly: pure
TypeScript, zero imports outside `src/heatmap/` and the colour/fixture types, grid-space fractional
column and row coordinates only, never display pixels, so the caller does the transform the same way
`resampleField` already does and a polygon always lands on the same field the base pass painted.
Keeping it import-light is what lets it run in the fast Node `unit` project rather than the browser
project.

Export `BandRing` (an ordered list of grid-space points plus a flag for whether the ring is an outer
boundary or a hole), `stitchBandRings(segments, cols, rows)` walking an unstitched `IsoSegment[]`
into closed rings, and `buildBandPolygons(values, cols, rows, bandLevels, flags?)` returning, per
band, the ring list that fills it.

The stitching algorithm is the whole risk of D-05 and `iso-lines.ts`'s header says so. Three parts,
each with a named failure mode the tests cover:

1. **Segment chaining.** Index segment endpoints by a quantised grid-space key so floating-point
   endpoints emitted from two adjacent marching-squares cells join. Quantise on the exact edge
   parameterization `iso-lines.ts` already produces (an endpoint always lies on a cell edge, so its
   key is that edge's identity plus its interpolation parameter) rather than on a rounded float,
   which is what makes the join exact rather than tolerance-based.
2. **Field-edge closure.** A chain whose two ends both terminate on the field rectangle's boundary
   is closed by walking the boundary between those two ends, in the direction that keeps the band's
   own interior on the correct side, inserting the rectangle corners the walk crosses. Determine the
   side by testing one grid value adjacent to the chain, never by assuming an orientation.
3. **Holes.** A ring fully contained inside another ring of the same band is a hole. Classify by a
   point-in-polygon test of one ring vertex against the candidate container. Fill with the canvas
   even-odd rule (`ctx.fill(path, 'evenodd')`) so an outer ring and its contained hole ring compose
   correctly without depending on winding direction, and state that choice in the module header.

Categorical cells: `marchingSquaresSegments` already skips any cell with a categorical corner, so no
iso-line is drawn through one. `buildBandPolygons` must go further and exclude the categorical cells'
own rectangles from every band polygon, because a band ring that merely routes around a categorical
region still fills across it if the region is interior. Emit the categorical cells' union as
additional hole rings on every band whose ring contains them.

Create `tests/heatmap/polygon-fill.test.ts` in the fast Node `unit` project covering all six
behaviors above, with analytic fields (a linear ramp, a bullseye, a constant field, a field with a
ruined block at the edge and another in the interior) rather than the committed fixture, so each
failure mode is isolated. This closes the third `07-VALIDATION.md` Wave 0 requirement.

No em dash characters. Minimize ternaries and never nest them.
  </action>
