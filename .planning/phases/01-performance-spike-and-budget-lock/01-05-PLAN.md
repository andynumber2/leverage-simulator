## Known Limitations (recorded honestly, not deferred)

1. **No GitHub remote exists in this repository.** `git remote -v` returns nothing. `.github/workflows/ci.yml` remains syntactically verified and never executed on real GitHub Actions infrastructure. Success criterion 5's literal wording ("a deliberately regressed commit fails CI on a budget breach") therefore cannot be demonstrated today, and this plan deliberately contains no task that pushes anything or blocks on a remote being configured. What this plan does prove is the strictly local half: a deliberately over-budget fixture makes the real harness exit non-zero with the correct message. Whether GitHub Actions then renders that non-zero exit as a red check is untested and stays untested until a remote exists.

2. **The self-test's spawned harness runs in a Node Vitest project, not headless Chromium.** The browser instance is not part of the exit-code path. The fixture exercises the identical `bench/global-setup.ts` teardown, the identical `buildFullRowSet`, the identical `assertRunInvariants`, and the identical Vitest exit-code machinery that `npm run bench` uses. Requiring a browser here would add roughly 15 seconds of Playwright startup to the fast unit suite on every pull request for zero additional coverage of the path under test. This deviation from D-09's literal "the actual bench command" is recorded here rather than hidden.

<assumption_delta_decision>
**Signal kind:** `pluralization`. The budget comparison began as one implementation (`checkBudget`) and became four: `checkBudget` plus three independently written inline assertions in the bench test files. WR-03 names this; Gap 1 is its direct consequence.

**The noun that is now primary:** the **bench run** (the full row set), not the individual bench test file. Enforcement identity moves from "one assertion per metric, written by whoever added the metric" to "one invariant over the run's rows, written once".

**Decision: promote.** `assertRunInvariants`'s new `verdict === 'fail'` check is promoted to the authoritative enforcement point. The per-file assertion is demoted to a fast, precise per-metric signal and is rewritten as a thin wrapper over the single `assertWithinBudget` comparison, so it can no longer drift from the authoritative check. The per-file assertions are kept, not deleted, because a run-level error naming a budget id is a worse failure message than a test failing next to the code that measured it.

**Rationale:** add-alongside is exactly what produced this gap. A second enforcement layer added beside the first, with no shared source of truth, is how the printed verdict and the process exit code came to disagree. Promoting the run-level check makes the per-file assertion optional for correctness and mandatory only for diagnostics, which is the correct inversion.

**Companion invariant test (adopted):** Task 1 adds a self-test that a fail verdict anywhere in the row set produces a non-zero exit. If a future phase reintroduces the singular assumption ("the per-file expect is the gate"), that test still holds, because it never touches a bench file.
</assumption_delta_decision>

<objective>
Make a budget breach fail the run structurally, and prove it end to end with a test that spawns a real harness command and asserts a non-zero exit code.

Right now the value that actually fails `npm run bench` is three separately written assertions in three bench files. `assertRunInvariants`, the one function with visibility into every row and the only code path that can fail a run independently of any test file, never looks at `row.verdict`. The self-test built specifically to prevent gate rot tests a pure function that has no process and no exit code. This plan inverts that: the run-level invariant becomes authoritative, the per-file assertion becomes a thin delegate over one shared comparison, and a spawned harness run against a deliberately over-budget fixture proves the exit code is non-zero.

Purpose: every later phase (2, 3, 4, 6, 7) inherits this gate. If it can rot into a no-op, every performance claim those phases make is unbacked.
Output: a run-level verdict backstop, one shared budget comparison, an isolated results directory, a `bench:selftest` harness command, an over-budget fixture, and a self-test that spawns it and asserts non-zero exit.
</objective>
