# Phase 8: UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope note: read before using this document

This phase adds three surfaces to an already-shipped screen: an export row (Copy link, relocated
under D-22, plus Export PNG and Export CSV), a Scenarios featured row plus overlay (D-14), and one
new loading state the DCA preset makes reachable for the first time (F-04). It does **not** touch
the heatmap, the equity curve, the metrics panel, or any other element `04-UI-SPEC.md` through
`07-UI-SPEC.md` already specified. All spacing, typography and base color tokens are reused
unchanged. This document states the reuse once per section and then adds only what is new.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none, hand-rolled Solid.js, continuing Phase 4/5/6/7's pattern |
| Icon library | none, no new icons; every new control in this phase is text-labeled, matching the existing hand-authored-SVG-only policy |
| Font | system stacks only, unchanged: UI text `system-ui, -apple-system, "Segoe UI", sans-serif`; numerics (CSV preamble is not rendered UI and carries no font requirement) `ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace` |

**Why no shadcn:** already settled in `04-UI-SPEC.md`, reconfirmed in `06-UI-SPEC.md` and
`07-UI-SPEC.md`: shadcn has no official Solid.js support. Not re-litigated here. `components.json`
is absent from the repo root, confirming the prior decision still holds.

**New runtime dependency this phase:** `html-to-image` (D-04, `08-RESEARCH.md`). It is a
rasterization library with no component surface of its own — it produces a `Blob` from an
existing DOM subtree — so it introduces no new visual vocabulary and is not a design-system
choice.

panel background), 30% secondary (surfaces, borders, body/label text), 10% accent, reserved for
the uses enumerated below and nothing else.

Reused unchanged from `04-UI-SPEC.md`:

| Role | Light | Dark | Usage in this phase |
|------|-------|------|----------------------|
| Dominant (60%) | `#F5F6F7` | `#14161A` | Page background, unchanged |
| Secondary (30%) | `#FFFFFF` / border `#E1E4E8` | `#1D2024` / border `#2B2F35` | Export row is not its own card (see Visual Hierarchy) — no new surface color; preset cards use this surface/border pair |

### Extended accent reservation this phase

Accent stays reserved for exactly the elements the prior phases already list, plus the two new
uses below. No other new element in this phase is accent-colored — specifically, **preset cards
are never accent-colored** (a card is a navigation affordance to a parameter set, not the app's
one explicit action, and accenting eight-plus cards would dilute the 10% ceiling the prior three
phases have held to).

- **Export PNG** and **Export CSV** buttons: styled identically to the existing `.copy-link-button`
  (accent text/border, transparent background, `border-radius: 4px`, 44px min-height). D-22
  groups all three as "three ways to get the same result out of the app, in one place" — they are
  visual siblings, not a hierarchy, so they share one treatment rather than one being promoted
  above the other two.
- Nothing else. The Scenarios overlay's "View all scenarios" trigger is deliberately **not**
  accent — it follows `.provenance-methodology-link`'s existing muted-link precedent ("reachable
  in one click, never accent-colored", Phase 5 D-17), since it is a navigation affordance, not the
  page's explicit action.

## Visual Hierarchy

1. **The screenshot region** (chart/heatmap, metrics, attribution, provenance): unchanged primary
   focal point from every prior phase.
2. **The export row**: sits directly below the screenshot region, outside it (D-21), styled as a
   row of three peer text buttons — no card, no background, no border around the row itself — so
   it reads as an action strip attached to the result, not a second panel competing with it.
3. **The featured preset row**: four cards below the export row (landing state) or below the
   parameter/result layout generally, styled as neutral bordered cards (same surface/border pair
   as `.result-column`/`.tier-option`), never accent, never styled to look more urgent than the
   result itself.
4. **The Scenarios overlay**: full-viewport, reuses `MethodologyOverlay`'s exact visual weight —
   it replaces the screen entirely while open, so it does not need to compete visually with
   anything underneath it.
5. **The DCA loading state**: lowest-weight, muted text only, no spinner or progress indicator
   (continuing Phase 7 D-14's "no spinner, bar, or percentage" convention for compute-in-progress
   states).

A treatment where the export row or the featured preset cards draw more visual attention than the
chart or the headline metric fails this hierarchy.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not a new single CTA: the export row is three peer actions — `"Copy link"` (unchanged label, relocated per D-22), `"Export PNG"`, `"Export CSV"` |
| Export PNG button, transient states | Mirrors `CopyLinkButton`'s three-state pattern: idle `"Export PNG"`, confirmed `"Copied!"` (clipboard path succeeded, D-23), failed `"Export failed"` (capture threw, or clipboard rejected AND the download fallback itself failed) |
| Export CSV button, transient states | idle `"Export CSV"`; no confirmed state needed (a download has no clipboard-style silent-success ambiguity to confirm — the browser's own download UI is the confirmation); failed `"Export failed"` if the Worker rejects |
| Export CSV, disabled in Sweep mode (D-08) | Button disabled; adjacent Label-size muted note, same treatment as `.tier-option-disabled-reason`: `"Switch to Single run to export a daily series."` |
| Export PNG/CSV, disabled before any result | No note needed — identical to `CopyLinkButton`'s existing unlabeled disabled state before a result exists |
| Empty state | Not applicable: the featured row and the Scenarios overlay are always fully populated from `presets.generated.ts` (D-18/D-19), never dependent on runtime data |
| Error state, PNG capture failure | `"Export failed — try again."` rendered inline beside the button, same recessive-but-destructive treatment as `CopyLinkButton`'s existing failed state (destructive color, Label size) |
| Error state, CSV worker failure | `"Export failed — try again."` (identical copy, same treatment) — one shared failure string for both export paths, not two separately-worded ones |
| Destructive confirmation | Not applicable: applying a preset overwrites the current parameter set the same way any other parameter change does (Phase 4 D-03: parameters compute live); no confirmation dialog, consistent with the app's zero-modal-dialog precedent for ordinary parameter changes |
| Scenarios trigger | `"View all scenarios"` — muted link, sits beside or below the featured row heading |
| Featured-row heading | `"Scenarios"` |
| Scenarios overlay title | `"Scenarios"` (reuses `MethodologyOverlay`'s title-role treatment) |
| Preset card title (example set, Claude's discretion for exact wording per `08-CONTEXT.md`) | One line naming the fund/index and the window, e.g. `"TQQQ through the COVID crash"`, `"UPRO through the COVID crash"`, `"3x S&P 500 from the 2000 peak"`, `"UPRO since inception"` |
| Preset card outcome line | One Label-size muted line stating the outcome, not the parameters, e.g. `"Real fund, real crash — down roughly {X}% at the bottom."` (exact figure sourced from `presets.generated.ts`'s build-time-computed outcome, per D-18, never hand-typed) |
| Preset card tag, synthetic (D-10) | `"Synthetic 3x, not the real fund"` — muted, same weight as `.default-badge` |
| Preset card tag, extended tier (D-11) | `"Extended tier — interpolated data"` — muted, same weight as `.default-badge`; clicking through still surfaces the full `ExtendedTierWarning` banner on the result screen itself (this tag is a preview, not a replacement for that banner) |
| DCA preset, in-flight compute (F-04) | While `solveIrr` resolves on the newly-applied DCA preset: the metrics panel's headline row shows `"Computing…"` in the muted Body role (`.loading-notice`'s existing class), replacing the numeric IRR figure only — every other panel (chart, provenance, attribution) keeps its previous complete state rather than blanking, matching Phase 7's "hold the previous complete state" convention for in-flight compute |

## UI Considerations

Authored against the shape-rooted UI-consideration taxonomy (empty / loading / error / populated
/ partial / overflow / zero-one-many / long-text), then reconciled against the
`ui-consideration-probe` coverage report run post-verification. Empty-state and error-state COPY
lives in `## Copywriting Contract` above; the rows below reference those strings rather than
restating them.

**Coverage: 3 elements, 24 applicable considerations, 15 resolved (12 explicit, 3 backstop), 9 dismissed with reason, 0 unresolved.**

### E1: ExportRow (Copy link / Export PNG / Export CSV, D-21/D-22/D-23)

_Kinds: interactive-control (confirmed; probe applied all 8 categories, none narrowed away)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | ✅ explicit | Before any result exists the row still renders all three buttons, disabled, with no note and no placeholder text, identical to `CopyLinkButton`'s existing unlabeled disabled state. The row is never hidden or collapsed, so the landing state and the result state have the same layout height |
| loading | ✅ explicit | There is no separate in-flight state. The buttons stay disabled while a run computes and enable on the completed result, reusing `CopyLinkButton`'s existing disabled condition unchanged for Copy link and extended to PNG/CSV |
| error | ✅ explicit | PNG capture failure and CSV worker failure both render `"Export failed — try again."` inline, destructive color, per the Copywriting Contract above |
| populated | ✅ explicit | Three buttons, fixed labels, `.copy-link-button`'s exact visual treatment shared across all three (accent outline, 44px min-height, transparent background) |
| partial | ✅ explicit | Export CSV is additionally disabled (with its own disabled-reason note) whenever `resultMode() === 'sweep'`, independent of whether a result exists — D-08's single-run-only constraint, not a loading state |
| overflow | 🧪 backstop | Verify at the narrowest supported viewport that three buttons plus an occasional disabled-reason note wrap or stack rather than overflowing the result column, following the same narrow-viewport check class `04-UI-SPEC.md` E5 established |
| zero-one-many | ✅ explicit | Always exactly three buttons, never conditionally hidden (CSV is disabled-in-place in sweep mode, never removed from the DOM, so the row's shape never changes) |
| long-text | dismissed | All three labels and both transient states are fixed short strings with no variable-length content |

### E2: Featured row + Scenarios overlay (D-13/D-14/D-15/D-20)

_Kinds: list-collection (confirmed; probe applied all 8 categories, none narrowed away)_

| Category | Status | Resolution / Reason |
|----------|--------|----------------------|
| empty | dismissed | Both the featured row and the overlay are always fully populated from a build-time-generated static list (D-18/D-19); there is no code path that produces zero presets |
| loading | ✅ explicit | Presets are static data bundled at build time, not fetched — the featured row and overlay render complete on first paint, with no loading state of their own (independent of whether the underlying bundle/manifest has finished loading, which is already covered by the app's existing top-level `loadStatus` gate) |
| error | dismissed | No independent fetch or compute step; applying a preset reuses the same validated-setter path as any other parameter change (`08-RESEARCH.md`'s Reusable Assets), so any invalidity is caught by the existing `APP-04` validation surface, not a new preset-specific error state |
| populated | ✅ explicit | Featured row: exactly 4 cards, ordered per D-13's unflattering-first rule (see below). Overlay: 8 or more cards (D-14), grouped in whatever order the preset library defines, each card identical in shape to a featured card |
| partial | dismissed | A preset library entry is either present or absent by construction (static list); there is no partially-loaded preset |
| overflow | 🧪 backstop | Verify the four-card featured row wraps to a narrower grid (2x2 or a single column) rather than overflowing horizontally at the app's existing 900px stacking breakpoint, and that the overlay's card grid (8+ cards) scrolls within `MethodologyOverlay`'s existing `overflow-y: auto` container rather than clipping |
| zero-one-many | ✅ explicit | Featured row is invariant at exactly 4 (D-15); the full library is invariant at "8 or more" (D-14) but not a fixed count, so the overlay's layout must not assume any specific card count beyond "at least 8" |
| long-text | 🧪 backstop | The high-rate financing preset's title plus its extended-tier tag plus its outcome line together are the longest combination of card content in the set; verify at the narrowest supported viewport that a card's text wraps within the card rather than being clipped or forcing the card wider than its grid cell |

**D-13's unflattering-first ordering, applied to the featured row:** `"TQQQ through the COVID
crash"`, `"UPRO through the COVID crash"`, `"3x S&P 500 from the 2000 peak"` (all three
unflattering), then `"UPRO since inception"` (the one flattering case) last. This is D-13's
general rule applied to D-15's specific four — D-15 names the set, D-13 governs the order they
render in.
