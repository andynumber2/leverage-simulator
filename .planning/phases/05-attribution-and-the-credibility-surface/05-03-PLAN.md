<objective>
Make the model checkable against a real product from inside the app (VALID-04): a permanently
reachable section that builds synthetic 3x from the bundled index, compares it against real
UPRO/TQQQ history, and prints both gates plus the full rate-regime breakdown.

**User story (MVP):** **As a** skeptic who will not run a test suite, **I want to** see synthetic
3x plotted against the real leveraged ETF with its tracking error stated, **so that** I can judge
whether this model matches reality before I accept anything else it says.

Purpose: VALID-04 exists because "the tests pass" was judged too weak a bar for a tool whose whole
claim is that its math is right.
Output: `src/validation/synthetic-comparison.ts` (the F-01 extraction) and a `ValidationSection`
mounted below the run layout.
</objective>

## Decisions taken under Claude's Discretion

- **The validation section is fragment-addressable, not permalink-parameterized.** CONTEXT.md left
  "whether the D-09 validation section is separately permalinkable" to discretion and
  `05-RESEARCH.md` Open Question 2 asked for a decision before wiring. Decision: the section gets
  `id="validation"` and is shareable as a URL fragment. No key is added to `PERMALINK_KEYS`,
  because `decodeParams`'s required-key sweep would then demand that key on every permalink
  generated before this phase. Fund selection stays in memory, defaulting to UPRO. Reversibility:
  reversible — a fragment is not part of the published query-param contract, so a later phase can
  promote fund selection to a real parameter without invalidating any existing link.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Parameter-column cost inputs -> validation computation | User-editable values flow into a computation whose output is a credibility claim. |
| Bundled manifest series -> synthetic construction | Build-time-controlled data; the series-id selection must not be user-steerable into a price-return leg. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Tampering | Synthetic construction leg selection | medium | mitigate | The series id is built from a fixed `total-return` suffix inside `ValidationSection.tsx` with no user-reachable path to `price-return`; an acceptance criterion greps for the absence of `price-return` in that file. Pairing a financing charge with a dividend-stripped leg was Phase 3's entire Gate 2 residual. |
| T-05-06 | Repudiation | Cost-parameter fitting | high | mitigate | The extracted module's head comment carries the no-fitting protocol binding both callers, and a plan-level prohibition forbids editing any `cost-parameters.ts` value in response to an in-app measurement. The existing CI gate test remains the enforcement point and is unchanged by the extraction. |
| T-05-07 | Information Disclosure | Sub-window table row suppression | medium | mitigate | Identical markup and class list on every regime row, asserted by a browser test, so an unflattering row cannot be selectively de-emphasized by a later edit without failing the test. |
| T-05-SC | Tampering | npm installs | low | accept | No package-manager install in this plan. |
</threat_model>
