<objective>
Put the user's own assumption on the chart beside what actually happened (ATTR-03), as a permanent
muted dashed series that never hides behind a toggle.

**User story (MVP):** **As a** person arguing about leveraged ETFs, **I want to** see the naive
leverage-times-return curve drawn on the same chart as the real one, **so that** the divergence
between the claim and the outcome is visible in a single pasted screenshot.

Purpose: D-07 — a comparison you have to flip between is absent from every screenshot, and the
screenshot is the deliverable.
Output: a pure `naive-series.ts` module and a second uPlot series in `EquityCurveChart.tsx`.
</objective>

  <behavior>
    - For a monotonically rising return series, every bar's naive value is finite and positive and the array contains no null.
    - For a window whose cumulative index return falls below negative one divided by leverage, every bar at or beyond that point whose naive value is non-positive is null, and the surrounding bars keep their numeric values.
    - For a window that dips below the non-positive threshold and later recovers above it, the returned array has numeric values, then nulls, then numeric values again: the array is never truncated and its length always equals the plotted bar count.
    - The naive value at the final plotted bar equals `computeAttribution`'s `naiveFinalValue` for the same inputs, within 1e-9 relative tolerance, for both the zero-contribution and the non-zero-contribution case.
    - An input bar count of zero returns a zero-length array without throwing.
  </behavior>
  <action>
    Create `src/app/components/ResultColumn/naive-series.ts` exporting
    `buildNaiveGhostData(inputs: KernelInputs, plottedBarCount: number): (number | null)[]`.

    It computes the naive portfolio value at every plotted bar using the same D-02/D-05 definition
    `src/validation/attribution.ts` uses for its final value: at bar `i`, the sum over every cash
    flow at or before `i` of `cashFlow * (1 + leverage * cumulativeIndexReturnFromThatCashFlowsBarTo_i)`,
    where `cumulativeIndexReturn` is the running product of `(1 + series.returns[k])` minus 1 and
    the initial investment is the cash flow at bar 0. Extract the shared per-bar cumulative-return
    walk rather than re-deriving a second, slightly different definition: import whatever
    `attribution.ts` already exports for this, and if `attribution.ts` exposes only the final value,
    add a narrow exported helper there rather than duplicating the recurrence here.

    Substitute `null` at every bar whose computed naive value is less than or equal to zero, and a
    number everywhere else. Do not truncate the array, do not stop at the first non-positive bar,
    and do not clamp to a small positive epsilon: uPlot's log distribution cannot render zero or a
    negative number, and unlike ruin a non-positive naive value is not an absorbing state, so the
    curve must be able to come back.

    The module contains no JSX and imports nothing from `solid-js` or `uplot`, so the Node unit
    project can test it directly, exactly as `log-axis-splits.ts` is tested today.

    Write `tests/app/naive-ghost-series.test.ts` covering every behavior above. Use the historical
    windows named in `05-RESEARCH.md` as the shape of the recovery case (a drawdown deeper than one
    over leverage followed by a recovery), constructed as a synthetic return array rather than
    requiring a bundle load.
