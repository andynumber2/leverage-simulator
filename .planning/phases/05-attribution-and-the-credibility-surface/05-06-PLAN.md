<objective>
Quantify the extended tier's bias and put the warning, with its measured magnitude, on every
extended-tier result (CRED-02, CRED-03).

**User story (MVP):** **As a** reader looking at a pre-1954 backtest, **I want to** be told that
the interpolated data understates volatility drag and by how much, **so that** I do not mistake a
flattered result for a real one in exactly the era the tier exists to reach.

Purpose: PITFALLS B2 and C4. The extended tier's whole reason for existing is also its weakest
point, and the warning is what keeps it honest.
Output: a measurement script, a committed generated figure with a pinning test, and the banner.
</objective>

    - Downsampling a daily series to month-end observations and interpolating back with `interpolateMonthlyToDaily` returns a series of the same length as the original over the same calendar window.
    - The reconstructed series' realized daily volatility over the measured era is strictly lower than the original daily series' realized volatility.
    - Running the same leverage and cost parameters over the original and the reconstructed series yields a volatility-drag component that is smaller in magnitude for the reconstructed series.
    - The measured bias is reported as an annualized figure, positive, meaning "drag understated by this much per year".
    - Re-running the measurement twice over the same committed bundle produces the identical figure to full float64 precision.
  </behavior>
  <action>
    Create `scripts/measure-extended-tier-bias.ts`, a standalone node script following the existing
    `--experimental-strip-types` convention. It loads the committed bundle, selects a known-good
    daily era and symbol (record both choices as named constants at the top of the file, with a
    comment stating why that era qualifies as known-good daily), downsamples that era's daily level
    series to month-end observations, interpolates back to daily by calling the bundle compiler's
    own `interpolateMonthlyToDaily` rather than reimplementing linear interpolation, and re-runs
    the simulation over both the original and the reconstructed series with identical leverage and
    cost parameters.

    The measured quantity is the difference in the annualized volatility-drag component between the
    two runs, computed through `computeAttribution` so the figure is the same drag definition the
    attribution panel reports. Express it as an annualized percentage of understated drag.

    `writeGeneratedPointerModule` uses, and emit a head comment marking the file generated and

    Add a `measure-extended-tier-bias` entry to `package.json`'s `scripts` block, alongside the
    existing `compile-data` entry and following its exact invocation shape. Do not wire the script

    Run the script once and commit its output.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build-time measurement -> committed source constant | A number produced by a script becomes a credibility claim rendered to users. |
| Committed bundle data -> measured figure | A data change can invalidate the committed figure silently. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-14 | Repudiation | Committed bias magnitude | high | mitigate | Task 2's pinning test recomputes the figure from the committed bundle on every CI run and fails the build on any mismatch, so a stale or hand-edited figure cannot ship. The failure mode this closes is a rendered credibility claim that the data no longer supports. |
| T-05-15 | Tampering | Interpolation method drift | medium | mitigate | The script calls the bundle compiler's own `interpolateMonthlyToDaily`; an acceptance criterion greps for the absence of a reimplemented interpolation. A measurement that inverts a different transform than the tier applies would report a number about nothing. |
| T-05-16 | Repudiation | Warning suppression | medium | mitigate | The component has no dismiss or acknowledgment path (grep-asserted), the banner is unconditional on the extended tier, and a browser test asserts it renders on repeated results. |
| T-05-SC | Tampering | npm installs | low | accept | No package-manager install in this plan; the new `package.json` entry is a script, not a dependency. |
</threat_model>
