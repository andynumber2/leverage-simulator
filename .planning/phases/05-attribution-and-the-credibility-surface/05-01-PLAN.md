<objective>
Deliver the cost decomposition that names which mechanism consumed the money (ATTR-01, ATTR-02),
end to end: a pure compute module, wired inside the existing coalesced recompute, rendered as an
always-visible panel under the metrics panel.

**User story (MVP):** **As a** skeptic reading a leveraged-ETF backtest, **I want to** see the gap
between the naive `leverage x return` claim and the actual result broken into volatility drag,
financing cost and expense ratio, **so that** I can tell which mechanism consumed the money instead
of taking the headline number on faith.

Purpose: PROJECT.md names attribution the headline feature. Without it the tool produces a number
but cannot say why.
Output: `src/validation/attribution.ts`, `AttributionPanel.tsx`, signed formatters in
`src/metrics/format.ts`, and the state wiring that makes them update with every parameter change.
</objective>

  <behavior>
    - Given a run with zero financing spread, zero short rate on every bar and zero expense ratio, the financing and expense components are both exactly 0 and volatility drag equals the whole gap.
    - Given leverage exactly 1, the financing component is exactly 0 regardless of the short-rate array, because the kernel scales financing by (leverage - 1).
    - Given leverage 1.01 and a strictly positive short rate on at least one bar, the financing component is strictly non-zero.
    - For arbitrary finite parameter combinations, the three component values sum to (naiveFinalValue - actualFinalValue) within 1e-6 relative tolerance.
    - The order in which the three factors are enumerated does not change any component value: permuting the internal factor order produces identical output.
    - A sustained-uptrend window produces a negative volatility-drag component (a gain), returned signed, with no clamping.
    - The financing-off arm produces a result identical to a run whose short-rate array is all zeros and whose financingSpread is 0, and differs from a run where only financingSpread is 0 whenever any bar carries a non-zero short rate.

    Extend `computeAttribution` to the full D-01/D-03 Shapley decomposition over three binary
    factors: `compounding`, `financing`, `expense`. Evaluate the value function over all eight
    subsets and reduce to three Shapley values, then add `volatilityDrag`, `financingCost` and
    `expenseRatio` (each a signed dollar amount) plus `volatilityDragShare`, `financingCostShare`
    and `expenseRatioShare` (each the component divided by `totalGap`, unclamped, signed) to
    `AttributionResult`.

    The four subsets containing `compounding` are real `runBacktest` calls. Build each arm's inputs
    by copying `inputs.params` and `inputs.series` and switching factors off as follows. Financing
    off requires BOTH `financingSpread: 0` AND a zero-filled `Float64Array` of the same length
    substituted for `series.shortRate` — setting only the spread leaves the base
    `(leverage - 1) * shortRate[i]` cost in an arm that is supposed to carry no financing at all.
    Expense off is `expenseRatio: 0`. Each arm needs its own preallocated `KernelOutputs` buffers,
    allocated once per call to `computeAttribution` (SIM-11: the kernel allocates nothing itself).
    The all-factors-on arm reads `actualResult.finalValue` rather than re-running the kernel.

    The four subsets without `compounding` start from Task 1's naive baseline and subtract simple,
    non-compounded annualized deductions accumulated over the same per-bar
    `series.calendarDaysElapsed` array the kernel uses. Financing deduction per bar:
    `principalOutstandingAtBar * (leverage - 1) * (series.shortRate[i] + params.financingSpread) * (series.calendarDaysElapsed[i] / FINANCING_DAY_COUNT_BASIS)`.
    Expense deduction per bar:
    `principalOutstandingAtBar * params.expenseRatio * (series.calendarDaysElapsed[i] / EXPENSE_DAY_COUNT_BASIS)`.
    `principalOutstandingAtBar` is `params.initialInvestment` plus every contribution flagged at or
    before bar `i`, matching D-05's per-cash-flow naive rule. Import both day-count constants from
    `src/kernel/backtest.types.ts`; do not re-declare either value locally and do not substitute an
    approximation such as 365.25 or a trading-day count.
