<objective>
Make the bench calibration score canonical per run. Today bench/kernel.bench.test.ts,
bench/sweep.bench.test.ts and bench/canvas-repaint.bench.test.ts each sample
`calibrationScore()` independently, so different rows in one run are denominated in different
scores, and `recordEnvironment` is last-write-wins, so the score printed in the environment
block is not necessarily the score that normalized any given row. GitHub Actions run
31963076671 attempt 1 printed 0.7375 in the environment block while PERF-03's own score was
1.4400 (1486.70 / 1032.43), a 2x divergence inside one run.

Purpose: every normalized figure this project records must be denominated in a score that is
reliably logged next to it. PERF-03 currently sits at 70.0% of budget, right on the D-20
escalation trigger, so the provenance of that exact number is load-bearing.

Output: a write-once, filesystem-backed canonical score shared through the existing
browser-to-Node commands bridge; all three bench files normalizing and stamping the environment
with it; a run-level invariant that fails any run whose rows and environment block disagree;
and unit coverage of the write-once semantics under more than one caller.

HARD CONSTRAINT: this plan changes only how the score is sampled, shared and recorded. It must
not change how the score is computed or applied. `NOMINAL_REFERENCE_MS` (40),
`REFERENCE_ITERATIONS`, `runReferenceLoop`, `REPEAT_COUNT` and `normalize()`'s scaling are
off limits (01-01-PLAN.md line 71). The anchor value is a separate open decision the user has
explicitly deferred and has not made.
</objective>

Existing shapes the new code must fit, read from source rather than assumed:

- `bench/accumulator-store.ts` is Node-only (`node:fs/promises`, `node:os`) and is deliberately
  never imported by a `*.bench.test.ts` file, because that would pull `node:` builtins into the
  browser bundle. All existing payloads cross the boundary as `browser.commands` entries whose
  Node-side implementations live in `vitest.config.ts`.
- `rawDir()` returns `join(process.cwd(), resolveBenchResultsDir(), '.raw')`.
  `resolveBenchResultsDir()` reads `BENCH_RESULTS_DIR`, rejects absolute paths and `..`
  segments, and defaults to `.bench`.
- `resetAccumulatorStore()` already does `rm(rawDir(), { recursive: true, force: true })` then
  `mkdir`, and is called once from `bench/global-setup.ts`'s setup phase. Anything written under
  `.raw/` is therefore per-run by construction.
- Existing persist functions return `Promise<void>`; existing load functions return the payload
  or `null`. Commands currently return `null`.
- `bench/browser-commands.d.ts` augments `declare module 'vitest/internal/browser'` with the
  `BrowserCommands` interface. A command that is not declared there types as `never` at the call
  site.
- `EnvironmentBlock.calibrationScore: number`; `captureEnvironment(calibrationScore: number)`
  runs in the browser context and returns `BrowserCapturedEnvironment` (`os` and `ci` are filled
  in Node-side by `persistEnvironment`).
- `assertRunInvariants(rows: readonly MeasurementRow[], totalRuntimeMs: number): void` in
  `bench/report.ts` is the authoritative run gate; throwing from it is what sets a non-zero exit
  code (`bench/global-setup.ts` sets `process.exitCode = 1` and rethrows). It already imports
  `type { EnvironmentBlock } from './environment-block.ts'`.
- `MeasurementRow.measuredMs` and `.normalizedMs` are both `number | null`, null exactly for
  unmeasured rows produced by `buildFullRowSet`.
- `tests/report.test.ts` calls `assertRunInvariants(rows, ms)` with two arguments in nine
  places; those call sites must keep compiling unchanged.
- The `bench` project sets `fileParallelism: false` today, so the three bench files run serially
  in practice. The write-once mechanism must still be correct if that ever changes: correctness
  cannot rest on a config flag that is set for an unrelated reason (D-02/D-03 noise isolation).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser test context to Node host process | `commands.claimCalibration(sample)` carries a browser-supplied number into a Node function that writes it to disk and makes it the denominator of every recorded figure |
| environment to filesystem path | `BENCH_RESULTS_DIR` composes into a path that `resetAccumulatorStore` recursively removes |
| concurrent callers to a single-writer file | two bench files may race to create `.raw/calibration.json` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-p8z-01 | Tampering | `claimCalibrationScore` sample argument | medium | mitigate | Reject non-finite, zero and negative samples before anything is written, so a broken sample can never become the run's denominator and propagate as `Infinity` or `NaN` through every figure (the same class of failure `normalize()` already guards) |
| T-p8z-02 | Tampering | `.raw/calibration.json` under concurrent claims | high | mitigate | Write to a unique temp file then `link()`, which is atomic and fails `EEXIST` rather than clobbering; no check-then-act existence test. Covered by the concurrent-callers test case in Task 1 |
| T-p8z-03 | Information disclosure / integrity of the record | environment block versus measured rows | high | mitigate | Task 3's score-coherence invariant in `assertRunInvariants` fails the run when any measured row's implied score disagrees with the recorded environment block |
| T-p8z-04 | Denial of service | `BENCH_TOTAL_RUNTIME_CAP_MS` | low | mitigate | The read-then-claim pair means the reference loop is sampled once per run rather than once per bench file, which reduces total bench runtime rather than increasing it |
| T-p8z-05 | Elevation of privilege | `BENCH_RESULTS_DIR` path composition | low | accept | Already mitigated by `resolveBenchResultsDir`'s existing absolute-path and `..` rejection; this plan adds no new path input and reuses `rawDir()` unchanged |
| T-p8z-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no packages: every module it touches already exists in the repo and every import is either a `node:` builtin (`node:fs/promises`, `node:crypto`) or an already-declared dependency (`vitest`) |
