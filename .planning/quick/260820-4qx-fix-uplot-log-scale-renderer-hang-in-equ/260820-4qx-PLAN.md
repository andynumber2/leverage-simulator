## Diagnosis (locked, already verified by the user, do NOT re-investigate)

- Repro: symbol NDX, leverage 10, entry 1999-03-04, default costs, log scale. The Chromium
  renderer hangs and the tab dies. Also reachable via QQQ at some leverages.
- Root cause: uPlot's built-in `logAxisSplits` (node_modules/uplot/dist/uPlot.esm.js:1495) never
  advances its `do...while` when the log y-scale minimum is below roughly 1e-22, because
  `roundDec(split, fixedDec.get(foundIncr))` snaps `split + foundIncr` back onto `split`. Infinite
  loop, renderer killed.
- Isolated against a bare uPlot instance with no app code involved: a y-range minimum at or above
  1e-22 renders fine, at or below 1e-23 crashes. Decade span is NOT the trigger (1e23 down to
  1e-5, 28 decades, renders fine).
- Why the app reaches it: NDX at 10x decays to 1.07e-24 at bar 2408 before its ruin bar, and
  `buildSeriesData` correctly plots every pre-ruin bar, so uPlot receives a y range bottoming at
  1e-24.

## Chosen fix (locked)

The user explicitly chose the custom-splits approach over (a) clamping the log y-range floor and
(b) truncating the series at a "practically dead" equity floor. Implement this and only this. Do
not clamp the scale range. Do not truncate the series. Do not propose an alternative.

Create `src/app/components/ResultColumn/log-axis-splits.ts` exporting a pure function
`logDecadeSplits(scaleMin: number, scaleMax: number): number[]`, generated from integer decade
exponents so every step advances by construction regardless of how small the minimum is. It is a
separate plain `.ts` module rather than another export inside `EquityCurveChart.tsx` because the
Node `unit` vitest project cannot parse the `.tsx` file (see the probe note in `<context>`); the
module doc comment must record that reason so nobody later "tidies" it back into the component.

Algorithm:
  - Return an empty array when either argument is not finite, or when either is less than or equal
    to zero. A log axis has no meaning there and an empty split list is what uPlot tolerates.
  - `lo` is the floor of the base-10 log of the smaller argument; `hi` is the ceiling of the
    base-10 log of the larger. Deriving both from min/max rather than trusting the argument order
    makes the function total even on a swapped call.
  - `step` is the max of 1 and the ceiling of `(hi - lo) / TARGET_DECADE_SPLIT_COUNT`, with
    `TARGET_DECADE_SPLIT_COUNT` an exported named constant set to 8. A step of at least 1 is the
    property that makes the loop terminate, and it is the whole point of the function.
  - Walk `e` from `lo` to `hi` inclusive by `step`, pushing `10 ** e`.
  - If the last pushed exponent is strictly less than `hi`, push `10 ** hi` as a final element, so
    the returned list always spans to at or above `scaleMax` even when `step` overshoots the top.
  - Drop any produced value that is not finite or not greater than zero, so an absurd exponent
    below the double-precision subnormal floor cannot emit two equal zeros and break strict
    monotonicity.
The result is strictly increasing, has at most `TARGET_DECADE_SPLIT_COUNT + 2` elements, and its
first element is at or below `scaleMin` and its last at or above `scaleMax`.

In `EquityCurveChart.tsx`, compute `const isLog = props.scale === 'log'` once in `rebuildChart`
next to the existing `distr` selection, and add three keys to the y-axis object (the second entry
of the `axes` array) ONLY when `isLog` is true. Leave the linear axis exactly as it is today, with
uPlot's own defaults for all three:
  - `splits`: a callback matching uPlot's signature `(self, axisIdx, scaleMin, scaleMax)` that
    ignores the first two parameters and delegates to `logDecadeSplits(scaleMin, scaleMax)`.
  - `filter`: identity, returning its `splits` argument unchanged. This is required, not optional:
    uPlot installs `log10AxisValsFilt` by default for a distr-3 / log-10 scale (uPlot.esm.js:3777)
    and it blanks any split that is not a 1eN value at the granularity it expects, which erases
    most of the generated splits.
  - `values`: a formatter over the split list. DELIBERATE ADDITION beyond the locked fix text,
    recorded here rather than made silently: uPlot's default `numAxisVals` formats through
    `Intl.NumberFormat` with 3 maximum fraction digits, so on the 1e-24 repro every generated
    decade below 1e-4 renders as the identical string "0" and the axis becomes unreadable. Format
    a value as `v.toExponential(0)` when its base-10 exponent is at or below -4 or at or above 13,
    and as `v.toLocaleString()` otherwise. Those thresholds are chosen so the landing run's
    ordinary equity magnitudes keep their existing grouped-decimal labels and the measured gutter
    stays wider than uPlot's 50px default, which `tracer.browser.test.ts` asserts.
`sizeYAxis` needs no change: uPlot passes it the already-formatted `values` strings, so it keeps
measuring exactly what the axis is about to draw.
