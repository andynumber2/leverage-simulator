# Quick Task 260824-52h: Isolate the 273.98ms Unexplained Residual Summary

**Instrumented one real full-grid sweep at the real pool boundary and found the 273.98ms PERF-03 residual is largely a narrow-arm extrapolation artifact, not a separate, tunable overhead cost.**

## Accomplishments

- Added an inert profiling seam to `src/sweep/sweep.worker.ts` (a module-scope boolean plus a
  Comlink-exposed `setChunkProfiling` setter), proven inert at runtime: a full-grid sweep with
  profiling never enabled emits exactly zero profile messages, on the real production path.
- Built `bench/sweep-residual.bench.test.ts`, which observes every chunk dispatch and response at
  the real `sweep-pool.ts` boundary via its existing `workerFactory` seam (no pool edit), capturing
  a 12-row per-chunk table for one real 10,000-cell sweep.
- Measured, at the real full-grid chunk shape (17 columns): buffer-allocation cost (0.03ms/grid),
  `mergeChunkResult` cost (0.01ms/grid), and serial `computeChunkMetrics` cost at span 2 versus
  span 17 (`spanRatio=0.51`) -- directly confirming 07.1-PERF-03-PROFILE.md's own unverified
  "per-column kernel cost is not perfectly linear" candidate.
- Found, via a direct (non-extrapolated) reconciliation computed in FINDINGS.md from the recorded
  per-chunk table, that real compute time summed and divided by worker count explains 98.3% of the
  measured wall clock on this sandbox, leaving only a 1.65% gap matched by measured worker-drain
  imbalance -- refuting the idea that a large, separately closeable pool-overhead cost exists.

## Decisions Made

- Combined Task 1 (tracer) and Task 2 (attribution) into a single commit and a single bench-file
  write. Both build on the exact same instrumented sweep; splitting them would have required
  either a second full-grid sweep (explicitly prohibited by the plan) or committing a
  Task-1-only version of the file mid-write, which is not how the file was actually developed.
  Each task's own `<verify>` block (typecheck, guardrail `git diff --exit-code`, the specific
  grep assertions) was run and passed against the finished file before moving on, so both
  gates are independently satisfied even though the commit is combined.
- Reported the plan's prescribed six-way `attributedMs`/`unattributedMs` sum exactly as specified
  (`unattributedMs=-323.88ms`), then added a second, non-overlapping reconciliation in
  FINDINGS.md (not a new bench measurement, arithmetic over the already-recorded per-chunk table)
  because the six-way sum double-counts overlapping wall-clock windows and does not, by itself,
  answer "how much is explained." This is disclosed explicitly in FINDINGS.md section 2, not
  substituted silently.
- Built the whole production bundle (`npm run build`) before the full `npm run bench` run:
  `bench/perf-07.bench.test.ts` and `bench/perf-08.bench.test.ts` require `dist/index.html` and
  failed with a clear error naming that requirement on the first attempt. This is a pre-existing
  environment precondition unrelated to this task's own changes, not a deviation in the sense of
  the deviation rules -- it is the documented way to run `npm run bench` in a fresh checkout.
