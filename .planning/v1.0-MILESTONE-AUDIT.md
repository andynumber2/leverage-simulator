# v1.0 Milestone Audit

**Verdict: `gaps_found`.** One requirement of 72 is unsatisfied, deliberately, with its evidence
and its decision both on record. No cross-phase integration break was found. Every other part of
the milestone is complete and verified.

This audit supersedes the 2026-08-18 version of this file, which was written when 3 of 8 phases
had executed and scored 28 of 72 requirements. That version is not a valid basis for closing v1.0.

## Scope

9 phases executed (01 through 08, plus inserted phase 07.1), 66 plans, all with SUMMARY.md.
All 9 now carry a VERIFICATION.md; 07.1's was written on 2026-08-27 during this audit, having
never existed.

## Requirements Coverage

71 of 72 satisfied. The traceability table in REQUIREMENTS.md, the per-phase VERIFICATION.md
requirements tables, and the SUMMARY.md `requirements-completed` frontmatter agree on all 71.

The exception is PERF-03. Under the audit's own status matrix a requirement owned by a
`gaps_found` phase is `unsatisfied`, which forces `gaps_found` on this milestone. That is the
correct and intended outcome: v1.0 closes with a known, measured, escalated miss rather than with
a silent gap. See the `gaps.requirements` block above for the full measurement history.

**The most important negative finding: there is no second copy of the simulation math.**
`runBacktest` in `src/kernel/backtest.ts` is the only production implementation of the recurrence.
Its callers are `src/app/state.ts` (single run), `src/sweep/sweep.worker.ts` (heatmap),
`src/validation/attribution.ts` (counterfactual arms), `scripts/compute-presets.ts` (build-time
preset figures), and the VALID gate test. `solveCagr`, `solveIrr`, `computeDerivedMetrics` and the
drawdown computation are likewise single-implementation. The independent reimplementations in
`tests/` are deliberate oracles and are excluded. Given that this project's stated core value is
that the simulation math is right and demonstrably right, a drifted second copy would have been
the worst possible finding, and there isn't one.

Attribution display wiring, flagged as unverified by the integration checker, was closed during
this audit: `state.ts:963` sets attribution inside the same commit function that sets
`kernelInputs`, `kernelResult` and `derivedMetrics`, so it cannot go stale relative to the
displayed run; the only other two call sites clear it to null on error and on reset;
`App.tsx:193` passes the live signal to `AttributionPanel`.

## End-to-End Flow

Raw CSV, to `compile-data`, to the binary bundle, to app load and decode, to a backtest with chart
and metrics, to a 10,000-cell heatmap sweep, to a PNG or CSV export or a shared permalink.

Wired end to end and exercised: `npm run typecheck` clean, `npm run test` 853/853 across 63 files,
`npm run test:app` 199/199 across 30 files, `npm run test:app:webkit` 9/9 including the 5 Safari
canvas-fidelity recurrence tests. The browser suites were run during this session at commit
`b6e692c`; HEAD has advanced only by documentation commits since.

## Nyquist Coverage

Partial. 3 phases reconciled (01, 02, 03), 6 at `status: draft` (04, 05, 06, 07, 07.1, 08). A
draft file means `validate-phase` never reconciled it, so its `nyquist_compliant` field is not

## Verdict

v1.0 is functionally complete. Every capability the milestone set out to build exists, is wired,
and is verified, and the product's core claim (that the simulation math is right and demonstrably
right against real leveraged ETF price history) is backed by a single-implementation kernel and a
passing UPRO/TQQQ tracking gate against the real bundled data.

The milestone does not meet its own definition of done, on one performance budget, and says so.
PERF-03 is unmet after five refuted levers, with the budget left at 1000ms rather than moved. The
bench suite's own runtime cap is likewise breached and visible rather than masked. Both are
recorded as decisions with evidence, not discovered as surprises.

Closing v1.0 from here means closing it with `status: gaps_found` and one named, evidenced,
deliberate miss. That is a defensible close for a project whose stated purpose is to be
believable, and it is a materially better record than a green audit would have been.
