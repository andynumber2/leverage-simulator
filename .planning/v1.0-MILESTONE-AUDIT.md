### Integration findings (warnings, not blockers)

**INT-01 — a silently dropped PERF-02 measurement would not turn the build red.**
`buildFullRowSet` synthesizes an `unmeasured` placeholder for any budget id with no recorded
measurement, and `assertRunInvariants` requires only that *at least one* row in the set be measured
(`bench/report.ts:278`, `rows.some((r) => r.verdict !== 'unmeasured')`). If `kernel.bench.test.ts`
were renamed, excluded by the `bench/**/*.bench.test.ts` glob, or skipped, the run would print
`PERF-02 | measured=n/a | verdict=unmeasured` and exit 0, with the other bench files satisfying the
invariant. A test *crash* is still caught, by Vitest's own exit code; only silent omission slips.
This is the same gate-rot class D-09 exists to prevent, one level up. Closing it needs a
per-requirement assertion: PERF-02 must be present with `source: 'production'`.

**INT-02 — synthesized placeholder rows are mislabeled.** The same path hardcodes
`source: 'spike-synthetic'` on every placeholder (`bench/report.ts:171`). For PERF-02 that is now
factually wrong, and `MeasurementSource`'s own documentation says a spike-synthetic figure must never
be presented as a production one. Reporting fidelity only; the `verdict` column carries the real
signal.

Both were confirmed by direct reading of `bench/report.ts`, not taken on the checker's report alone.
